\begin{abstract}
Long-term-memory agents are evaluated end-to-end: a wrong answer is scored
wrong, and nothing is learned about \emph{where} the pipeline broke. We argue
that this measurement gap hides the dominant failure mode of memory systems,
and we fix the instrument. We present \protocol{}, a frozen protocol that
attributes every wrong answer to a specific boundary of a nine-stage memory
lifecycle (conversation $\rightarrow$ formation $\rightarrow$ storage $\rightarrow$
evolution $\rightarrow$ retrieval $\rightarrow$ reranking $\rightarrow$ context
$\rightarrow$ reasoning $\rightarrow$ answer). Three design choices make the
attribution reliable: an anti-circular evidence-sufficiency gate that compares
gold evidence against the benchmark reference answer rather than the model's
own prediction; a semantic decision layer in which lexical metrics never enter
attribution; and three orthogonal control conditions---Real Memory, Oracle
Memory (gold injected as formed memories into an independent engine), and
Oracle Context (gold injected directly into the context)---that separate
retrieval-side from reasoning-side failures. Running the protocol on two
long-term-memory benchmarks (LongMemEval-s and LoCoMo) with paired statistics
and a judge-reliability study, we find that the dominant boundary is
\emph{formation}, not retrieval: real memory loses a large fraction of gold
evidence before it ever reaches the store, and once evidence reaches the
final context the answer model rarely fails. The protocol, the measurement
validity fixes it required, and the full per-question traces are released as
an open artifact.
\end{abstract}

\section{Introduction}

Agent memory systems---retrieval-augmented stores, consolidation pipelines,
reflective memories---are increasingly the substrate of long-horizon LLM
agents, and they are evaluated almost exclusively end-to-end: answer a
question over a long conversation, score the answer. That score conflates
every way the system can fail. A missing fact, a superseded belief, a
retrieval miss, a truncated context window, and a reasoning slip all produce
the same observable: a wrong answer.

Prior work on memory failures either taxonomizes errors post-hoc from traces
or reports aggregate accuracy, and the attribution instruments underneath
carry three measurement problems that we document and fix here: (i)~lexical
scorers (exact match, token F1) are used as ground truth for correctness,
conflating representation failures with reasoning failures; (ii)~evidence
matches by lineage (a fact citing a source turn) are treated as content
preservation; (iii)~``oracle'' controls are under-specified---injecting gold
evidence into the \emph{context} and injecting it into \emph{memory} are
different interventions, and equating them misattributes retrieval failures
to reasoning.

\paragraph{Contributions.}
\begin{enumerate}
\item \textbf{A frozen attribution protocol.} \protocol{} labels every wrong
answer with the earliest lifecycle boundary at which gold evidence is not
fully present, with an evidence-sufficiency gate (\ezero{}) that is
anti-circular by construction and a semantic-judge decision layer. All
thresholds are frozen before any large-scale run (\S\ref{sec:protocol}).
\item \textbf{Three orthogonal control conditions.} Real Memory, Oracle
Memory, and Oracle Context, each measured with its own stage trace. Oracle
Memory injects gold evidence as formed memories into an independent engine
that runs the full retrieval/reranking/context pipeline; Oracle Context
bypasses it. The two controls bound where a failure can live.
\item \textbf{Measurement-validity fixes with regression tests.} Provenance
matches require content preservation; semantic evidence matching requires
faithful representation rather than topical overlap; deterministic evaluator
channels are narrowed to quote/date rules; embedding-backend failures are
loud rather than silently degrading. Each fix ships with regression tests,
including two calibration-period false negatives that pinned the bugs.
\item \textbf{An empirical study on two benchmarks} with paired statistics
(exact McNemar, paired bootstrap CIs), per-question-type breakdowns, a
cross-model replication, and an inter-judge agreement study. The dominant
failure boundary is \emph{formation}; reasoning failures (F6 candidates) are
rare and mostly control failures of the oracle conditions.
\end{enumerate}

\section{Related Work}

\paragraph{Long-term memory benchmarks.} LongMemEval \cite{longmemeval} evaluates
chat assistants over long histories with question types that stress
extraction, temporal reasoning, and knowledge updates; LoCoMo
\cite{locomo} evaluates very long multi-session conversations. We use both as
evidence-boundary substrates and treat their gold evidence spans as the
lifecycle signal.

\paragraph{Memory architectures.} RAG-style stores \cite{retrieval-augmented-generation,bm25},
consolidation and reflection pipelines \cite{generative-agents,memgpt,reflexion},
and recent agent-memory systems \cite{mem0,mnemonic,memobase} optimize recall
or answer accuracy. These works report what the system remembers or
answers; ours reports \emph{where along the lifecycle} the evidence was
lost, on a concrete open implementation, so the protocol's claims are
checkable rather than asserted.

\paragraph{Failure analysis and attribution.} Error taxonomies for agents
and RAG failure analyses \cite{survey-memory-agents} typically
require human trace reading, and long-context degradation studies
\cite{lost-in-middle} characterize attention-side loss rather than
memory-pipeline loss. Our protocol automates the lifecycle attribution
while keeping the human in the loop for judge reliability
(\S\ref{sec:results}).

\paragraph{Evaluation methodology.} LLM-as-judge and semantic evaluation
\cite{llm-as-judge,g-eval}; judge reliability and self-preference bias
\cite{metamemory}; uncertainty and abstention \cite{metamemory}.
We measure inter-judge agreement explicitly (Cohen's $\kappa$, Study 2E)
and keep the judge model separate from the answer model in the
cross-model design (Study 2D). For condition comparisons we use exact
McNemar tests \cite{exact-mcnemar} with paired bootstrap CIs
\cite{efron-bootstrap}, and treat questions within one conversation as
correlated \cite{dietterich-nested}, reporting per-type breakdowns rather
than pooling silently.

\section{Protocol: Lifecycle-Boundary Attribution}
\label{sec:protocol}

\paragraph{Lifecycle.}
Conversation $\rightarrow$ Formation $\rightarrow$ Storage $\rightarrow$
Evolution $\rightarrow$ Retrieval $\rightarrow$ Reranking $\rightarrow$
Context $\rightarrow$ Reasoning $\rightarrow$ Answer. Each arrow is a
measurable boundary with its own artifact set.

\paragraph{Labels.}
\fone{} (evidence never formed), \ftwo{} (formed but not stored),
\fthree{} (stored but superseded/dropped by governance), \ffour{} (in store
but not retrieved), \ffive{} (retrieved but dropped by reranking),
\fsix{} \textsc{\_candidate} (all evidence reached context, answer still
wrong), \ezero{} (gold evidence insufficient for the reference answer),
\evaluncertain{} (judge undecided), \rcfailure{} (oracle control answered
wrong).

\paragraph{Decision order.}
(1)~Semantic verdict on the model answer; correct $\rightarrow$ no failure.
(2)~Undecided $\rightarrow$ \evaluncertain{}. (3)~E0 gate: is the gold
evidence sufficient for the \emph{benchmark reference answer} (never the
model prediction)? Insufficient $\rightarrow$ \ezero{}. (4)~Earliest
lifecycle stage whose artifact set does not fully contain the gold evidence
$\rightarrow$ F1--F5. (5)~All stages reached and answer still wrong
$\rightarrow$ \fsix{} \textsc{\_candidate}.

\paragraph{Evidence matching tiers.}
Exact text $\rightarrow$ provenance \emph{with content-preservation check}
(shared content vocabulary $\geq 50\%$ of the smaller side and
$\geq \min(2, |gold|)$ shared tokens; rejected matches are reported as
\verb|provenance_only|) $\rightarrow$ semantic (faithful-representation
containment at 0.8, either direction, same absolute floor). Raw-token
overlap is never a match: two same-topic different-event evidence items
(``\ldots the park on 9 May 2023'' vs ``\ldots the park on 7 May 2023'')
score 0.56 under the legacy rule and are conflated, which is one mechanism
behind inflated legacy recall.

\paragraph{Unmeasured stages.}
Stages a condition does not measure carry \verb|measured: false| and are
skipped, never read as perfect recall. Oracle Context, for example, bypasses
the pipeline; its unmeasured stages are excluded from stage recall.

\paragraph{Embedding-backend discipline.}
Embeddings serve retrieval only; attribution runs on content. A failing
embedding request is retried and then fails the record loudly (hash
fallback is opt-in offline mode); inputs exceeding the backend context
window are deterministically halved; every run is verified dimension-clean
afterwards (\S\ref{sec:design}).

\section{Experimental Design}
\label{sec:design}

\paragraph{System under test.}
A concrete open implementation: a deterministic rule-based analyzer
(facts, relations, events, rules, profiles), an embedding store with dense
retrieval and reranking, context assembly, and a local answer model
(\texttt{qwen2.5:7b}, temperature 0; \texttt{gemma3:12b} cross-check),
\texttt{bge-m3} embeddings. The analyzer makes no LLM calls; only answer
generation, semantic judging, and embeddings hit the model server.

\paragraph{Conditions.}
\textbf{Real Memory}: full pipeline over the conversation.
\textbf{Oracle Memory}: gold evidence injected as formed active facts into
an independent engine, then the full retrieval/reranking/context pipeline.
\textbf{Oracle Context}: gold evidence placed directly into the answer
context, bypassing the pipeline. The three conditions partition failure
responsibility: Real vs.\ Oracle Memory isolates the memory-side loss;
Oracle Memory vs.\ Oracle Context isolates context assembly; Oracle
Context's own wrong answers are \rcfailure{}.

\paragraph{Datasets and sampling.}
LongMemEval-s (n=10 full haystack, protocol replication); LongMemEval
oracle subset (n=50, two-stage stratified by conversation and question
type, largest-remainder allocation, per-type minimum of one, fixed seed);
LoCoMo (n=50, stratified by conversation). Question-level subsets are
committed with sampling recipes; conversations are joined at load time from
the local full data; raw benchmark data is not redistributed.

\paragraph{Metrics and statistics.}
Per-condition semantic accuracy (judge verdict; lexical EM/F1 reported in
parallel, never as attribution input); per-stage recall; failure-label
distribution. Condition comparisons use exact McNemar tests on discordant
pairs and paired bootstrap percentile CIs (10,000 resamples). Judge
reliability uses Cohen's $\kappa$ between the primary judge and a second
judge model re-judging the \emph{same stored answers}.

\paragraph{Hypotheses.}
\textbf{H1}: Real Memory loses a significant fraction of gold evidence
before context; F1/F4/F5 dominate over F6 candidates.
\textbf{H2}: Oracle Memory $\gg$ Oracle Context accuracy implies
retrieval/context assembly, not reasoning, is the bottleneck.
\textbf{H3}: Real-vs-oracle inversions (oracle wrong, real right) are
control failures, not evidence of reasoning strength.

\section{Results}
\label{sec:results}

\paragraph{Study 2A (protocol replication, n=10, full haystack).}
Three-condition independence holds in the strict-mode rerun: Real Memory
7/10 semantic accuracy, Oracle Memory 10/10, Oracle Context 10/10. The
real-vs-oracle gap is directionally large ($+0.300$) but not significant at
$n{=}10$ (exact McNemar $b{=}3$, $c{=}0$, $p{=}0.25$; bootstrap CI
$[+0.000, +0.600]$)---this study exists to validate the protocol, not to
estimate effects. First losses: \fone{}$\times$8, \fthree{}$\times$1,
context$\times$1; stage recall formation 0.200, storage 1.000, evolution
0.100, retrieval 1.000, rerank 1.000, context 0.650. The E0 gate finds all
10 items evidence-sufficient. Calibration-period false negatives (e47becba,
58bf7951) are explained by the formation boundary.

\paragraph{Study 2B (primary, n=50).}
Table~\ref{tab:2b} reports the strict-mode rerun (post-C8 fix; embedding
backend verified clean: 119 databases, 7{,}000 vectors, all 1024-dim).
Semantic accuracy (uncertain verdicts excluded from the denominator) is
66.0\% for Real Memory (31/47), 83.3\% for Oracle Memory (40/48), and
75.0\% for Oracle Context (36/48). Real Memory loses gold evidence at the
\emph{formation} boundary in 45/50 cases (90\%): formation recall 0.236 and
evolution recall 0.236, against storage 1.0, retrieval 1.0, rerank 0.987,
and context 0.695. Oracle Memory restores every pre-context stage to 1.0
and reaches 0.979 context recall; its remaining three failures are
context-assembly, not formation. The E0 gate finds 40/50 benchmark items
carry sufficient evidence, 8 insufficient (reported as \ezero{}, not as
memory failures), and 2 uncertain (excluded). Among attributable answer
failures, \fone{} dominates (9), followed by \ezero{} (7) and
\evaluncertain{} (3); zero \fsix{} candidates occur, because gold evidence
never survives formation.

Real versus Oracle Memory is significant: exact McNemar on discordant
pairs $b{=}10$, $c{=}2$, $p{=}0.0386$; paired bootstrap (10{,}000 resamples)
95\% CI on the accuracy difference $[+0.043, +0.319]$. Real versus Oracle
Context is marginal ($b{=}6$, $c{=}1$, $p{=}0.1250$, CI $[+0.000, +0.217]$),
consistent with H2: repairing evidence availability (Oracle Memory) closes
most of the gap, while bypassing the pipeline (Oracle Context) closes less.
Per question type (Table~\ref{tab:2b-type}), the formation dominance is
broadest on multi-session and temporal-reasoning items (4 \fone{} each)
and weakest on single-session-user/assistant items (1.0 accuracy in all
conditions). The pre-fix run (real 58.3\%, oracle memory 72.9\%, oracle
context 70.2\%) is retained in the artifact as an audit reference only.

The shift concerns the retrieval side. In Study 2B the real-memory stage
recall was 1.0 at retrieval and 0.99 at reranking; on LoCoMo it drops to
0.61 and 0.53, and retrieval-side failures appear for the first time
(\ffour{} 12.5\% of answer failures). Long, topically diffuse
conversations thus move part of the loss downstream of formation: the
extractor still loses the majority of evidence (formation recall
0.097), but the subset it does store is no longer always retrievable.
Lexical false negatives are even stronger here (lexical 28.0\% vs.\
semantic 52.0\% on real answers), reinforcing that lexical scoring
would misattribute most of these failures.

\paragraph{Study 2D (cross-model, gemma3:12b).}
Replacing the answer model with \texttt{gemma3:12b} (judge unchanged:
\texttt{qwen2.5:7b}) tests which parts of the attribution are properties
of the memory pipeline rather than of the answer model. The lifecycle
side is unchanged exactly as the protocol predicts: real-memory stage
recall is identical to Study 2B (formation 0.236, first loss \fone{}
45/50), because extraction never invokes the answer model. The answer
side compresses: semantic accuracy is 28/47 = 59.6\% (real) vs.\
32/49 = 65.3\% (oracle memory) vs.\ 34/49 = 69.4\% (oracle context).
The real-vs-oracle-memory contrast loses significance
($b{=}7$, $c{=}4$, $p{=}0.549$, CI $[-0.064, +0.213]$)---a weaker
answer model leaves less headroom for the oracle advantage to
express---while real vs.\ oracle context remains directional with
$c{=}0$ (real never beats oracle context; $b{=}5$,
$p{=}0.063$, CI $[+0.021, +0.191]$). One inversion appears in the
multi-session type (real 0.500 vs.\ oracle memory 0.417), consistent
with oracle injection occasionally crowding the context. The
cross-model design also bounds judge dependence: the judge model is
held fixed across 2B and 2D, so the lifecycle labels---formation
dominance in particular---cannot be artifacts of judge--answer model
co-adaptation, and Study 2E directly measures the judge axis.

\paragraph{Study 2E (judge reliability).}
Gemma3:12b re-judges the stored answers of a seeded 20-record subsample
of Study 2B (seed 20261018; 55 paired verdicts across the three
conditions). Raw agreement between the two judge families is 43/55 =
78.2\%, but Cohen's $\kappa$ over the three-way verdict
(correct/incorrect/uncertain) is low: $\kappa = 0.158$. The gap between
raw agreement and $\kappa$ is a prevalence effect (41/55 verdicts are
agree-correct), and the disagreements are asymmetric: in 10 of 12
incorrect-disagreements the stricter qwen2.5:7b judge says
\emph{incorrect} where gemma3:12b says \emph{correct}, concentrated on
borderline cases (answers that require a small arithmetic step from the
evidence, or superlatives supported by a single evidence item); gemma
also resolves two of qwen's \emph{uncertain} verdicts as correct. Two
consequences for the protocol. First, headline semantic accuracy has a
judge-sensitive borderline band, and single-judge numbers should be
read with that band in mind. Second, and more importantly, the
lifecycle attribution that constitutes our main claim is
judge-independent: stage recall is computed from pipeline artifacts,
not from verdicts, so the formation-dominance result (first loss
\fone{} 45/50 in 2B; identical stage recall in 2D) cannot be an
artifact of judge choice. The judge only enters at the
failure/no-failure boundary and in the E0/EVAL outcomes, which is
exactly where we report its measured disagreement.

\section{Analysis}

\paragraph{Where memory fails.}
The stage-recall chain localizes the loss: formation recall is the lowest
measured boundary, and context recall is high once evidence is stored. This
is an architectural statement: coverage of the extractor, not retrieval
quality, is the binding constraint for the systems under test. In Study 2B
the pattern is sharp---45/50 real-memory runs lose gold evidence at
formation (recall 0.236), while storage, retrieval, and reranking are at or
near ceiling (1.000, 1.000, 0.987). Once Oracle Memory injects gold as
formed facts, every pre-context stage returns to 1.000 and only three
context-assembly failures remain. The deficit is therefore almost entirely
upstream of retrieval: improving rankers or context windows cannot recover
evidence the extractor never formed.

\paragraph{The boundary moves with workload shape.}
Study 2C replicates formation dominance on a second benchmark
(first loss \fone{} 46/50, recall 0.097) and adds a boundary condition:
on long, topically diffuse multi-session conversations ($\sim$600
messages/question), part of the loss migrates downstream of formation.
Retrieval-stage recall falls from 1.000 (Study 2B) to 0.608, reranking
from 0.987 to 0.527, and \ffour{} appears among answer failures
(3/24). The attribution protocol makes this shift visible instead of
averaging it away: formation remains the primary boundary on both
benchmarks, but its share is a property of the workload, not a
constant---shorter curated histories lose evidence almost entirely at
formation, while long conversational histories additionally stress
retrieval and reranking.

\paragraph{Why end-to-end accuracy misleads.}
Lexical scoring produces false negatives on concise correct answers, which
the semantic layer resolves; conversely, lineage matches without content
preservation inflate recall. Both effects move attributed failures toward
the wrong boundary---and both are regression-tested. In Study 2B, lexical
accuracy under real memory (38.0\%) sits 28 points below the semantic
verdict (66.0\%): a system evaluated lexically would look retrieval-broken
when it is extraction-broken.

\paragraph{What the E0 gate changes.}
Before any failure label, the gate asks whether the benchmark's own
reference answer is recoverable from the gold evidence. In Study 2B, 8/50
items fail this check (and 2 are judge-uncertain), i.e., 20\% of the
nominal error budget is benchmark evidence insufficiency or judge
uncertainty, not memory failure. Protocols that skip this gate silently
convert benchmark noise into system failures; we report \ezero{} and
\evaluncertain{} as first-class outcomes.

\paragraph{Oracle inversions.}
Real-vs-oracle inversions are labeled \rcfailure{} and reported separately;
they bound how much of an oracle deficit is reasoning-side. In Study 2B,
two records are correct under Real Memory but wrong under Oracle Memory
($c{=}2$): the oracle pipeline is not uniformly better, and the
paired statistic accounts for it. Oracle Context---which bypasses the
pipeline---answers 75.0\% despite having perfect context, so reasoning on
perfect evidence is itself imperfect; this is why H2 is stated as
Oracle Memory $\gg$ Oracle Context rather than oracle perfection.

\section{Limitations}
\label{sec:limitations}

Sample sizes are n=50 per benchmark with two answer models; estimates carry
the corresponding uncertainty (reported as paired bootstrap CIs). The
analyzer is rule-based, so formation-boundary numbers characterize this
implementation family, not all memory systems. The judge is an LLM: Study~2E
measures cross-family judge disagreement and finds a prevalence-inflated
raw agreement ($\kappa=0.158$) with a systematic leniency asymmetry on
borderline cases, so headline semantic accuracies carry a judge-sensitive
band; our core attribution claims are judge-independent (stage recall is
artifact-based), but E0/EVAL outcome counts are not, and human adjudication
of a disagreement sample remains future work. LoCoMo category semantics were
mapped from question inspection and secondary documentation rather than an
authoritative legend. Benchmarks are English conversational QA; temporal and
multi-hop question types are represented but not exhaustively. The public
artifact must be anonymized for review per the current call.

\section{Conclusion}

We presented \protocol{}, a frozen protocol that turns a wrong answer into
a lifecycle attribution, with three oracle controls, measurement-validity
fixes backed by regression tests, and paired-statistics reporting. On two
benchmarks and two answer models, the dominant failure boundary is
formation, not retrieval or reasoning---a conclusion invisible to
end-to-end accuracy and to attribution instruments that conflate lineage
with content or lexical with semantic correctness.

\section*{Responsible NLP Checklist}

\paragraph{Datasets.} LongMemEval-s \cite{longmemeval} and LoCoMo
\cite{locomo}, both publicly released for research. We use published
question-level subsets (LongMemEval-s, LongMemEval oracle subset, LoCoMo)
and join conversations at load time from the local full data; raw
benchmark text is not redistributed in the artifact (dataset versions and
licenses are recorded in the artifact manifest). Both benchmarks contain
English conversational dialogues; the subset used here contains no
multi-modal records.

\paragraph{Personal data.} Both benchmarks are synthetic or licensed
fictional dialogues; no personal data of the authors or annotators is
used. Speaker names are pseudonyms internal to the benchmarks.

\paragraph{Models and compute.} Answer models \texttt{qwen2.5:7b}
\cite{qwen25} and \texttt{gemma3:12b}, embedding model \texttt{bge-m3}
\cite{bge-m3}, all served locally via Ollama with recorded digests. Total
compute is single-GPU (laptop-class, 8\,GB VRAM); the full pipeline runs
in a few hours per study.

\paragraph{Intended use and misuse.} The protocol is intended for
diagnosing memory-system failures in research settings. It is not a
leaderboard metric: attribution characterizes the concrete implementation
family under test (rule-based analyzer plus dense retrieval), and
stage-boundary numbers should not be quoted as properties of other
architectures. Automated attribution may mislabel cases where gold
evidence is ambiguous; we therefore report \ezero{} and \evaluncertain{}
separately instead of forcing a failure label.

\paragraph{Anonymization.} The public artifact will be anonymized for
review (author-identifying metadata stripped; a separate anonymous branch
is prepared by \texttt{scripts/make\_anonymous\_branch.sh}, with a
verification grep and a fresh-repo push recipe for full history
anonymization); model-server endpoints and paths are scrubbed.

\section{Protocol Pseudocode}
\label{app:pseudocode}

The attribution decision order is frozen in \texttt{docs/PROTOCOL.md} and
implemented once in \texttt{evaluation/attribution.py}. Lexical scores are
computed for reporting only and never enter this procedure.

\begingroup\scriptsize
\begin{verbatim}
def attribute(answer, gold, ref, stages):
    v = verdict(answer, gold)
    if v == CORRECT:                  # (1)
        return NO_FAILURE
    if v == UNCERTAIN:                # (2)
        return EVAL_SEMANTIC_UNCERTAIN
    if not sufficient(gold, ref):     # (3) E0 gate
        return E0_EVIDENCE_INSUFFICIENT
    for stage in [FORMATION,          # (4) F1-F5
                  STORAGE, EVOLUTION,
                  RETRIEVAL, RERANKING]:
        if not covers(stages[stage], gold):
            return FAILURE_LABEL[stage]
    return F6_REASONING_CANDIDATE     # (5)
\end{verbatim}
\endgroup

Frozen thresholds: content-preservation check --- shared content
vocabulary $\geq 50\%$ of the smaller side and $\geq \min(2, |gold|)$
shared tokens; semantic tier --- directional containment $\geq 0.8$ with
the same absolute floor; deterministic judge support R1 --- shared span
covers $\geq 0.8$ of the candidate (verbatim-quote cases only);
deterministic judge support R2 --- pure date/relative expressions that
resolve to the same date as timestamped evidence. \verb|provenance_only|
matches are reported as diagnostics, never as stage coverage.

\section{Per-Question Attribution Tables}
\label{app:traces}

Every study writes one JSON object per question to
\verb|comparison.jsonl| with: the question and benchmark answer; the gold
evidence spans (with ids and timestamps); per-condition answers; the
semantic verdicts and judge metadata; the per-stage artifact coverage used
by the attribution decision; the assigned failure label; and the code

an artifact alongside the paper; Table~\ref{tab:2b} and
Table~\ref{tab:2b-type} aggregate them.

\section{Judge Prompts and Normalization}
\label{app:judge}

The semantic judge is prompted to decide whether the model answer is
correct \emph{given the gold evidence}, and to answer
\texttt{yes}/\texttt{no}/\texttt{uncertain} with a one-line rationale;
the judge never sees the benchmark reference answer (the E0 gate owns that
comparison) and never sees lexical scores. Two deterministic channels
repair judge output before it is accepted, both deliberately narrow:
\textbf{R1 lexical} accepts a \texttt{no} verdict only when the candidate
is essentially a verbatim quote of the evidence (shared span covers
$\geq 0.8$ of the candidate); \textbf{R2 temporal} accepts pure
date/relative expressions that resolve to the same date as timestamped
evidence. Anything wider passed wrong answers during calibration
(``went to the park'' style candidates), which is why the thresholds are
frozen and regression-tested. The cross-model judge (Study 2E) uses the
same prompt with \texttt{gemma3:12b}; agreement is reported as Cohen's
$\kappa$ on the shared subsample.

\section{Stratification Recipes}
\label{app:stratification}

Study subsets are built by \texttt{experiments/build\_study\_set.py}.
Primary stratum: conversation (or session group) so that no single
conversation dominates and within-conversation correlation is spread
across the sample; secondary stratum: question type. Allocation is
proportional by largest remainder, with a minimum of one question per
type present in a conversation. Seed 20261018 for all studies. Committed
subsets store question-level records only; conversations are joined at
load time from the local full dataset, and raw benchmark text is not
redistributed.

\section{Statistical Procedures}
\label{app:stats}

Condition comparisons are paired by question. \textbf{Exact McNemar}: with
$b$ questions correct only under condition A and $c$ correct only under
condition B, the two-sided exact $p$-value is the binomial tail
$2\min(P(X\leq \min(b,c)), P(X\geq \max(b,c)))$ with $X\sim
\mathrm{Binomial}(b{+}c, 0.5)$ under the null. \textbf{Paired bootstrap
CI}: 10{,}000 resamples of question indices; percentile interval of the
per-question accuracy difference. \textbf{Cohen's $\kappa$}
(Study 2E): $\kappa = (p_o - p_e)/(1 - p_e)$ over the verdict categories
\texttt{correct}/\texttt{incorrect}/\texttt{uncertain}, computed on the
seeded subsample of Study 2B that both judges re-score. Because questions
within one conversation are correlated, we report per-type breakdowns
alongside pooled numbers and treat pooled $p$-values as optimistic
\cite{dietterich-nested}.
