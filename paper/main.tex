\begin{abstract}
Long-term-memory agents are evaluated end-to-end: a wrong answer is scored
wrong, and nothing is learned about \emph{where} the pipeline broke. We
present \protocol{}, a frozen protocol that attributes every wrong answer
to a specific boundary of a nine-stage memory lifecycle (conversation
$\rightarrow$ formation $\rightarrow$ storage $\rightarrow$ evolution
$\rightarrow$ retrieval $\rightarrow$ reranking $\rightarrow$ context
$\rightarrow$ reasoning $\rightarrow$ answer). Three design choices make
the attribution reliable: an anti-circular evidence-sufficiency gate that
compares gold evidence against the benchmark reference answer rather than
the model's own prediction; a semantic decision layer in which lexical
metrics never enter attribution; and two oracle controls---gold injected
as formed memories into an independent engine vs.\ directly into the
context---that separate retrieval-side from reasoning-side failures.
Running the frozen protocol on two benchmarks (LongMemEval-s and LoCoMo),
three answer models, two formation extractors, and an external
open-source memory stack (Mem0's OSS pipeline with a local extractor),
with paired statistics and an adjudicated
judge-reliability study, we find that the dominant boundary is
\emph{formation}, not retrieval: real memory loses a large fraction of
gold evidence before it ever reaches the store---an attribution
computed from pipeline artifacts, independent of answer-level
judgments. The boundary is a
property of the extractor, not of the pipeline---swapping the formation
extractor inside one fixed pipeline collapses the oracle-memory advantage
from +17.3 points to zero---and it shifts downstream on long
conversations; the same label structure and gate criticality reproduce on
Mem0's OSS stack. An attribution protocol rather than a single bottleneck claim is
the transferable contribution. The protocol, the measurement-validity
fixes it required (each with regression tests), and the full
per-question traces are released as an open artifact.
\end{abstract}

\section{Introduction}

Agent memory systems---retrieval-augmented stores, consolidation pipelines,
reflective memories---are increasingly the substrate of long-horizon LLM
agents, and they are evaluated almost exclusively end-to-end: answer a
question over a long conversation, score the answer. That score conflates
every way the system can fail. A missing fact, a superseded belief, a
retrieval miss, a truncated context window, and a reasoning slip all produce
the same observable: a wrong answer.

Prior work on memory failures either taxonomizes errors post-hoc from traces
or reports aggregate accuracy, and the attribution instruments underneath
carry three measurement problems that we document and fix here: (i)~lexical
scorers (exact match, token F1) are used as ground truth for correctness,
conflating representation failures with reasoning failures; (ii)~evidence
matches by lineage (a fact citing a source turn) are treated as content
preservation; (iii)~``oracle'' controls are under-specified---injecting gold
evidence into the \emph{context} and injecting it into \emph{memory} are
different interventions, and equating them misattributes retrieval failures
to reasoning. Previewing the answer: the bottleneck sits in the
\emph{formation-stage implementation}, not the pipeline---and which stage
binds moves with extractor, retriever, and workload.

\paragraph{Contributions.}
\begin{enumerate}
\item \textbf{A frozen attribution protocol with an anti-circular evidence
gate.} \protocol{} labels every wrong answer with the earliest lifecycle
boundary at which gold evidence is not fully present. Before any failure
label is assigned, an \ezero{} gate asks whether the benchmark's own
reference answer is recoverable from the gold evidence---comparing against
the reference rather than the model's prediction, which breaks the
``wrong answer $\to$ missing evidence $\to$ blame memory'' circularity. All
thresholds are frozen before any large-scale run (\S\ref{sec:protocol}).
\item \textbf{Measurement-validity fixes, each with regression tests.}
Lexical scores never enter attribution; provenance matches require
content preservation; semantic evidence matching requires faithful
representation rather than topical overlap; deterministic judge channels
are narrowed to quote/date rules; embedding-backend failures fail loudly
instead of silently degrading.
\item \textbf{A judge-reliability study with author adjudication.} We
measure inter-judge agreement (Cohen's $\kappa$) between two judge models
on a seeded subsample, adjudicate every disagreement against gold
evidence under published guidelines, validate the adjudication against
two further blind judge families, and report how the headline numbers
move under the adjudicated verdicts (Study 2E)---to our knowledge the
first adjudicated judge-reliability measurement in long-term memory
evaluation.
\item \textbf{An empirical study on two benchmarks, three answer models, and
two formation extractors, plus an external open-source memory stack
(Mem0's OSS pipeline with a local extractor),} with paired statistics (exact McNemar, paired
bootstrap CIs), per-question-type breakdowns, and a cross-model
replication. The dominant failure boundary is \emph{formation}; reasoning
failures (F6 candidates) are rare and mostly control failures of the
oracle conditions. An extractor ablation (Study 2F) shows the boundary
is a property of the formation stage, not of one rule-based
implementation: with an LLM-driven extractor the oracle-memory advantage
collapses from $+17.3$ points to zero. An external-system replication
(Study 3A) shows the failure taxonomy transfers to an independent stack.
\end{enumerate}

The three-condition design (Real Memory / Oracle Memory / Oracle Context)
is the measurement instrument these contributions run on, not a
contribution in itself: oracle-style controls have become common
\cite{memtrace,memtier}. What is new is the protocol around them.

\section{Related Work}

\paragraph{Long-term memory benchmarks.} LongMemEval \cite{longmemeval} evaluates
chat assistants over long histories with question types that stress
extraction, temporal reasoning, and knowledge updates; LoCoMo
\cite{locomo} evaluates very long multi-session conversations. We use both as
evidence-boundary substrates and treat their gold evidence spans as the
lifecycle signal.

\paragraph{Memory architectures.} RAG-style stores \cite{retrieval-augmented-generation,bm25},
consolidation and reflection pipelines \cite{generative-agents,memgpt,reflexion},
and recent agent-memory systems \cite{mem0,mnemonic,memobase} optimize recall
or answer accuracy. They report what the system remembers or answers;
ours reports \emph{where along the lifecycle} the evidence was lost, on a
concrete open implementation, so the protocol's claims are checkable
rather than asserted.

\paragraph{Failure analysis and attribution.} Error taxonomies for agents
and RAG failure analyses \cite{survey-memory-agents} typically require
human trace reading; long-context degradation studies
\cite{lost-in-middle} characterize attention-side rather than
memory-pipeline loss. Our protocol automates lifecycle attribution with
measured judge reliability (\S\ref{sec:results}).

\paragraph{Diagnosing where memory fails (2024--2026).} A first wave of
automated failure-attribution work targets multi-agent systems: Who\&When
localizes the responsible agent and decisive step \cite{whowhen};
AgenTracer labels failure traces by counterfactual replay \cite{agentracer};
AgentDebug classifies errors into memory, reflection, planning, action,
and system modules \cite{agentdebug}. Two 2026 preprints probe long-term
memory systems specifically, with instructively different conclusions.
MemTrace reports the dominant bottleneck as \emph{evidence use}, not
retrieval: when systems fail, the evidence was retrievable ten times more
often than it was missing \cite{memtrace}. MEMTIER analyzes retrieval
bottlenecks in a tiered architecture on LongMemEval-S \cite{memtier}. A
concurrent LoCoMo diagnostic goes further: Yuan et al.~\cite{memory-probe}
report that retrieval method dominates (a 20-point spread) while write
strategy moves accuracy 3--8 points, and that raw chunk storage with zero
LLM calls beats expensive extraction. We read the four-way
divergence---MemTrace's ``evidence use'', MEMTIER's and Yuan et al.'s
``retrieval'', our formation dominance---as the motivation for a protocol
rather than a contradiction: the dominant boundary is a property of
(write-path quality $\times$ retrieval quality $\times$ workload shape),
so no pooled score can locate it (\S\ref{sec:analysis}). Study 2F isolates
the write-path variable inside one fixed pipeline, Study 2C shifts the
workload, Study 3A varies the system. Our claim is the attribution
protocol around the now-common oracle controls
\cite{memtrace,memtier,memory-probe}, not the oracle construction.

\paragraph{Evaluation methodology.} LLM-as-judge and semantic evaluation
\cite{llm-as-judge,g-eval}; judge reliability and self-preference bias,
uncertainty and abstention \cite{metamemory}. We measure inter-judge
agreement explicitly (Cohen's $\kappa$, Study 2E). For condition
comparisons we use exact McNemar tests \cite{exact-mcnemar} with paired
bootstrap CIs \cite{efron-bootstrap}, and treat questions within one
conversation as correlated \cite{dietterich-nested}, reporting per-type
breakdowns rather than pooling silently.

\section{Protocol: Lifecycle-Boundary Attribution}
\label{sec:protocol}

\paragraph{Lifecycle.}
Conversation $\rightarrow$ Formation $\rightarrow$ Storage $\rightarrow$
Evolution $\rightarrow$ Retrieval $\rightarrow$ Reranking $\rightarrow$
Context $\rightarrow$ Reasoning $\rightarrow$ Answer. Each arrow is a
measurable boundary with its own artifact set.

\paragraph{Labels.}
\fone{} (evidence never formed), \ftwo{} (formed but not stored),
\fthree{} (stored but superseded/dropped by governance), \ffour{} (in store
but not retrieved), \ffive{} (retrieved but dropped by reranking),
\fsix{} \textsc{\_candidate} (all evidence reached context, answer still
wrong), \ezero{} (gold evidence insufficient for the reference answer),
\evaluncertain{} (judge undecided), \rcfailure{} (oracle control answered
wrong).

\paragraph{Decision order.}
(1)~Semantic verdict on the model answer; correct $\rightarrow$ no failure.
(2)~Undecided $\rightarrow$ \evaluncertain{}. (3)~E0 gate: is the gold
evidence sufficient for the \emph{benchmark reference answer} (never the
model prediction)? Insufficient $\rightarrow$ \ezero{}. (4)~Earliest
lifecycle stage whose artifact set does not fully contain the gold evidence
$\rightarrow$ F1--F5. (5)~All stages reached and answer still wrong
$\rightarrow$ \fsix{} \textsc{\_candidate}.

\paragraph{Evidence matching tiers.}
Exact text $\rightarrow$ provenance \emph{with content-preservation check}
(shared content vocabulary $\geq 50\%$ of the smaller side and
$\geq \min(2, |gold|)$ shared tokens; rejected matches are reported as
\verb|provenance_only|) $\rightarrow$ semantic (faithful-representation
containment at 0.8, either direction, same absolute floor). Raw-token
overlap is never a match: same-topic different-event items (``the park on
9 May'' vs ``7 May 2023'') score 0.56 under the legacy rule and are
conflated---one mechanism behind inflated legacy recall.

\paragraph{Unmeasured stages.}
Stages a condition does not measure carry \verb|measured: false| and are
skipped, never read as perfect recall. Oracle Context, for example,
bypasses the pipeline; its unmeasured stages are excluded from stage
recall.

\paragraph{Embedding-backend discipline.}
Embeddings serve retrieval only; attribution runs on content. A failing
embedding request is retried, then fails the record loudly (hash
fallback is opt-in offline mode); inputs exceeding the backend context
window are deterministically halved; runs are verified dimension-clean
afterwards (\S\ref{sec:design}).

\section{Experimental Design}
\label{sec:design}

\paragraph{System under test.}
A concrete open implementation: a formation extractor, an embedding store
with dense retrieval and reranking, context assembly, and a local answer
model (\texttt{qwen2.5:7b}, temperature 0; \texttt{gemma3:12b} cross-check),
\texttt{bge-m3} embeddings. The formation extractor has two arms behind
one interface: a deterministic rule-based analyzer (facts, relations,
events, rules, profiles) and an LLM-driven extractor
(\texttt{qwen2.5:7b}, Study 2F). Everything downstream of formation---
governance, storage, retrieval, reranking, context assembly---is
identical across arms, so the extractor is the only varying component.
The rule arm makes no LLM calls; only answer generation, semantic
judging, embeddings, and the 2F extraction arm hit the server.

\paragraph{Conditions.}
\textbf{Real Memory}: full pipeline over the conversation.
\textbf{Oracle Memory}: gold evidence injected as formed active facts into
an independent engine, then the full retrieval/reranking/context pipeline.
\textbf{Oracle Context}: gold evidence placed directly into the answer
context, bypassing the pipeline. The conditions partition failure
responsibility: Real vs.\ Oracle Memory isolates memory-side loss; Oracle
Memory vs.\ Oracle Context isolates context assembly; Oracle Context's
own wrong answers are \rcfailure{}.

\paragraph{Datasets and sampling.}
LongMemEval-s ($n{=}10$ full haystack, protocol replication); the
LongMemEval oracle subset (a primary $n{=}200$ run plus a two-stage
stratified $n{=}50$ pilot, reused by the controlled ablations
2D/2E/2F); LoCoMo ($n{=}50$). The primary run takes the \emph{first 200
items} of the oracle source; the source file is type-ordered, so these
are exactly the three harder LongMemEval types (knowledge-update,
multi-session, temporal-reasoning)---a \emph{hard-subset protocol},
not a random sample. Its accuracy levels are therefore not comparable
to full-benchmark numbers, nor to the pilot (which stratifies over all
six types, ${\sim}40\%$ hard items); all 2B conclusions are conditional
on the hard subset. One question per conversation holds (200/200), so
question-level and cluster-robust inference coincide. Stratification
recipes and seeds are in Appendix~\ref{app:stratification}; raw
benchmark data is not redistributed.

\paragraph{Metrics and statistics.}
Per-condition semantic accuracy (judge verdict; lexical EM/F1 reported in
parallel, never as attribution input); per-stage recall; failure-label
distribution. Condition comparisons use exact McNemar tests on discordant
pairs and paired bootstrap CIs (10,000 resamples); judge reliability uses
Cohen's $\kappa$ on the \emph{same stored answers} re-judged by a second
model.

\paragraph{Hypotheses.}
\textbf{H1}: Real Memory loses a significant fraction of gold evidence
before context; F1/F4/F5 dominate over F6 candidates.
\textbf{H2}: Both oracle conditions exceed Real Memory while Oracle
Context stays below ceiling, so evidence availability dominates the gap
and reasoning on perfect evidence remains imperfect.
\textbf{H3}: Real-vs-oracle inversions (oracle wrong, real right) are
control failures, not evidence of reasoning strength.

\section{Results}
\label{sec:results}

\paragraph{Study 2A (protocol replication, n=10, full haystack).}
Three-condition independence holds in the strict-mode rerun: Real Memory
7/10, Oracle Memory 10/10, Oracle Context 10/10; the real-vs-oracle gap
is directionally large ($+0.300$) but not significant at $n{=}10$
(McNemar $p{=}0.25$, CI $[+0.000, +0.600]$)---this study validates the
protocol, not estimates effects. First losses \fone{}$\times$8,
\fthree{}$\times$1, context$\times$1; E0 passes all 10 items.

\paragraph{Study 2B (primary, n=200).}
Table~\ref{tab:2b} reports the scaled run on the LongMemEval oracle
subset ($n{=}200$; answer and judge model \texttt{deepseek-v4.1-flash},
temperature 0). The lifecycle-side attribution comes first and is
judge-free---computed from pipeline artifacts, never from verdicts:
Real Memory loses gold evidence at the \emph{formation} boundary in
155/200 cases (77.5\%; recall 0.427, 95\% CI $[0.375, 0.480]$) while
storage/retrieval sit at 1.000, rerank at 0.990, context at 0.896
(Table~\ref{tab:2b}); evolution recall ties formation mechanically.
Oracle Memory restores every pre-context stage to 1.0, its residual
losses being context-assembly (0.951), not formation. Answer-level
accuracy (over decided verdicts; judge-dependent, quantified below) is
59.2\% for Real Memory (113/191), 76.9\% for Oracle Memory (143/186),
and 87.6\% for Oracle Context (169/193); 9/14/7 rows remain undecided.
The run's judge left 134 exact-match answers (text identical to the gold
string) unjudged; we count them correct via a deterministic exact-match
channel---the narrowest rule in the frozen stack. The E0 gate finds
153/200 items evidence-sufficient, 41 insufficient (\ezero{}, not memory
failures). Among the 87 real-memory runs not judged correct
(78 wrong, 9 undecided: 6 API errors, 3 abstentions), \fone{} dominates
(61, 70\%), then \ezero{} (10), \evaluncertain{} (8), \fsix{} (3); one
\ffour{} and one \ffive{} occur, because gold evidence rarely survives
formation. Disabling the gate reclassifies all 10 \ezero{} items as
lifecycle failures (9 as \fone{}), inflating \fone{} 61$\to$72 (+18\%)
and the formation share 70\%$\to$83\%: the gate is load-bearing, not
cosmetic.

Both oracle contrasts are large under the primary judge. Real versus Oracle Memory:
McNemar $b{=}40$, $c{=}7$, $p{<}0.0001$. Real versus Oracle Context:
$b{=}62$, $c{=}7$, $p{<}0.0001$ (cluster-robust by conversation:
identical; one question per conversation, 200/200). The
oracle-versus-oracle contrast is significant
here---Oracle Context exceeds Oracle Memory ($b{=}28$, $c{=}6$,
$p{=}0.0002$)---but the ordering reverses in the $n{=}50$ qwen pilot
and vanishes in 3A, so we read the oracle contrast as one combined
\emph{real $\ll$ oracle} effect (H2): Oracle Context below ceiling shows
reasoning on perfect evidence is itself imperfect. Because the judge is
shared with the answer model, these answer-level gaps---their
\emph{levels} in particular---are corroborating evidence whose
judge-dependence is quantified below; the lifecycle-side attribution
never consults the judge.

\paragraph{Sensitivity to uncertain exclusions.}
The conditions exclude different fractions of undecided verdicts
(9/14/7 after the exact-match repair; pre-repair 37/61/66), so we
checked whether the headlines depend on the exclusion rule. Counting
every remaining undecided verdict as \emph{wrong} gives 56.5/71.5/84.5\%
and leaves every contrast significant (Real-vs-OM $b{=}44$, $c{=}14$,
$p{=}0.0001$; Real-vs-OC $b{=}67$, $c{=}11$, $p{<}0.0001$; OM-vs-OC
$p{<}0.0001$). The pre-repair exclusions themselves were mostly exact
matches to the gold answer (75.7--89.4\% vs.\ 0\% among judged rows),
so the earlier protocol---which reported 52.1/69.1/82.1\% with those
rows excluded---\emph{understated} all three conditions, the oracle
conditions most; the corrected counting widens Real-vs-Oracle-Memory
from $+16.9$ to $+17.7$ points. The remaining exclusions (6/9/2) are
transient API errors (Appendix~\ref{app:stats}).

\paragraph{Cross-family re-judge of the primary run (self-judging
control).}
The 2B answer model and judge are the same family, so the headline
rates could inherit self-preference bias. A strictly blind re-judge
(question, answer, gold evidence only) of a seeded 30-record subsample
(90 answers) with \texttt{qwen2.5:7b}---the family 2E calibrates---gives
raw agreement 10/25, 15/23, 16/24, $\kappa{=}{-}0.21/{+}0.17/{+}0.14$
(Real/OM/OC, against the corrected verdicts). On the paired subsample
the primary contrast is \emph{not} robust to judge family:
Real-vs-Oracle-Memory flips sign ($+0.250$ deepseek, $p{=}0.065$,
$\to$ $-0.080$ qwen, $p{=}0.69$) and Real-vs-Oracle-Context drops
to $+0.000$ ($p{=}1.0$), qwen being more lenient on Real answers
and stricter on oracle answers. The direction is consistent with
self-preference inflating the oracle conditions, but qwen is also the
less truth-consistent family in 2E (8/14 vs.\ 13/16), so we cannot
separate judge noise from self-preference at $n{=}30$. Extrapolating
the subsample flip rates to the full decided sets estimates a movement
large enough to reverse the primary gap (Real $+12$, Oracle Memory
$-26$, Oracle Context $-17$ points), though imprecise at $n{=}25$--$29$
both-decided pairs. We therefore read the 2B answer-level \emph{levels}
as judge-dependent at the ten-point scale, and the judge-free
formation-side attribution as the load-bearing result. Per-type accuracy
and the attributed failure labels for the three hard types are aggregated
in Appendix~\ref{app:traces}.

\paragraph{Study 2C (cross-benchmark, LoCoMo n=50).}
LoCoMo questions sit in much longer multi-session conversations
($\sim$600 messages across $\sim$28 sessions, versus $\sim$115K-token
histories in 2B), testing whether the formation-dominant boundary
survives a change of benchmark and workload shape. It does, with one
informative shift. Semantic accuracy is
26/50 = 52.0\% (real) vs.\ 36/50 = 72.0\% (oracle memory) vs.\
37/50 = 74.0\% (oracle context); both oracle contrasts are significant
(real vs.\ oracle memory: $b{=}15$, $c{=}5$, $p{=}0.0414$, CI
$[+0.040, +0.360]$; real vs.\ oracle context: $b{=}16$, $c{=}5$,
$p{=}0.0266$, CI $[+0.040, +0.380]$). First loss is again concentrated
at formation (\fone{} 46/50); the answer-failure distribution is
\fone{}$\times$18, \ezero{}$\times$3, \ffour{}$\times$3 (E0 gate: 47
sufficient, 3 insufficient). The shift is on the retrieval side:
retrieval recall falls 1.000$\to$0.608 (CI $[0.483, 0.728]$) and
reranking 0.990$\to$0.527 (CI $[0.398, 0.655]$) once conversations grow
to hundreds of messages, so \ffour{} losses appear (3/24 attributable).
Formation recall is even lower than 2B (0.097, CI $[0.028, 0.182]$):
the boundary moves with the workload but stays pre-context. The
per-category breakdown is in Appendix~\ref{app:traces}.

Lexical false negatives are even stronger on LoCoMo (28.0\% vs.\ 52.0\%
on real answers), reinforcing that lexical scoring would misattribute
most of these failures.

\paragraph{Study 2D (cross-answer-model control, $n{=}50$ subset).}
Swapping the answer model \texttt{qwen2.5:7b} for \texttt{gemma3:12b}
(judge fixed) on the pilot subset leaves the lifecycle side unchanged
as the protocol predicts---stage recall is identical across answer
models (formation 0.236, first loss \fone{} 45/50), because extraction
never invokes the answer model. Only the answer side
moves: qwen scored 66.0/83.3/75.0\% and gemma compresses to
59.6/65.3/69.4\% (real/oracle memory/oracle context), the
real-vs-oracle-memory contrast losing significance ($b{=}7$, $c{=}4$,
$p{=}0.549$) while real vs.\ oracle context stays directional ($c{=}0$;
$b{=}5$, $p{=}0.063$); the oracle ordering again flips. With the judge
fixed across answer models, formation dominance cannot be an artifact of
judge--answer-model co-adaptation.

\paragraph{Study 2E (judge reliability and adjudication).}
Gemma3:12b re-judges the stored answers of a seeded 20-record subsample
(60 answers, 55 paired, 5 abstentions): raw agreement 43/55 = 78.2\%,
Cohen's $\kappa$ = 0.158---a prevalence effect; judges disagree only
inside a 14-verdict borderline band. We adjudicated every disagreement
(16 total, 14 decidable): qwen matches adjudicated truth 8/14, gemma
3/14 (lenient: 9 over-acceptances, 0 over-rejections). Denominators are
tabulated in Appendix~\ref{app:judge-ledger}; the rule stack resolves
9/60 identically for any judge.

\paragraph{Blind validation of the adjudication (two external families).}
We re-judge the same 60 answers under the identical prompt and rules,
strictly blind, with two families that cannot have co-adapted with
either primary judge. DeepSeek (\texttt{deepseek-v4.1-flash}, API)
reproduces the adjudication on 13/16 cases (13/14 decidable) while
agreeing with neither primary judge; a fourth family (Mistral
\texttt{mistral:7b}, local) does \emph{not} corroborate on the
borderline band (1/14 with adjudicated truth, siding with the lenient
gemma judge). The four families sort by leniency rather than noise
(Appendix~\ref{app:judge-ledger}), with borderline-band agreement in the
same order (13/16 $>$ 8/14 $>$ 3/14 $>$ 1/14); on the 41-item consensus
core all agree (41/41). The adjudication aligns with the \emph{strictest}
judge family---we cannot exclude that strictness itself explains part of
that alignment. Applying the adjudicated verdicts moves the pilot's
numbers at most 4.2 points, leaves the ordering unchanged, and
\emph{strengthens} the primary contrast. At $n{=}200$ scale the blind
cross-family check above is the corresponding test, and it is less
favorable.
\paragraph{Study 2F (extractor ablation, n=50).}
The cleanest single-variable control: same 50 LongMemEval-s oracle
questions, answer model, judge, embeddings, and lifecycle stages---only
the formation extractor changes (rule analyzer $\to$ LLM-driven). The
formation stage observes 2{,}262 memory items against 335 for the rule
arm ($6.8\times$). Formation recall rises 0.236$\to$0.838, evolution
0.236$\to$0.802, context 0.695$\to$0.847; first loss is \fone{} in 13/50
instead of 45/50, and 29/50 questions (was 5/50) lose no gold evidence at
any stage.

The oracle conditions collapse. Oracle Memory still repairs
every pre-context stage to 1.000 (context 0.979, three context-assembly
failures), but its answer-level advantage disappears: 70.8\% (34/48)
real vs.\ 71.4\% (35/49) oracle memory vs.\ 70.8\% (34/48) oracle
context, real-vs-oracle-memory $b{=}4$, $c{=}4$, $p{=}1.0000$, CI
$[-0.125, +0.125]$---against $+0.170$, $p{=}0.0386$ under the rule
extractor. The failure mix shifts from the evidence side to the
evaluation side: \fone{} drops 9$\to$3, \ezero{} 7$\to$6, and \fsix{}
(sufficient evidence, full context, wrong answer) appears for the first
time, 4 cases, alongside 2 \evaluncertain{} and 1 \ffive{}. Formation
dominance is thus a property of the extractor, not of the pipeline.

Two caveats bound this reading. (i)~Source coupling: extractor and answer
model share a family (\texttt{qwen2.5:7b}), which can only \emph{inflate}
the real-memory condition, so the collapsed oracle gap is, if anything,
an underestimate of extractor dependence; the lifecycle-side measurements
it rests on are answer-model invariant (Study~2D). (ii)~Scale: the
residual \fsix{} budget is not a small-answer-model artifact---at API
scale (Study~2B, $n{=}200$) \fsix{} is 3 of the 87 runs not judged
correct (3.4\%).

\paragraph{Study 3A (external-system replication: Mem0's OSS stack, $n{=}50$).}
The protocol is system-agnostic: an adapter feeds a memory system's
artifacts to the frozen attribution code, which matches evidence by
content. We re-run the identical protocol---same 50 LongMemEval oracle
questions, same answer model and judge (\texttt{qwen2.5:7b})---on
\emph{Mem0's OSS stack} \cite{mem0} (v2.2.1, config in
Appendix~\ref{app:env}): its own \texttt{qwen2.5:7b} fact extraction,
\texttt{bge-m3} embeddings, a Chroma store, and 4-message ingestion
chunks. Extraction, embeddings and store are independent of our
pipeline; the extractor \emph{model} is shared, so this replicates the
storage stack, not the extractor. Across 283 extraction calls no update
or delete event ever fires, so Mem0's signature update machinery is
inactive in this workload. Semantic accuracy: Real Memory 58.3\%
(28/48), Oracle Memory 79.6\% (39/49), Oracle Context 77.1\% (37/48).
Both oracle contrasts survive on the external system (real vs.\ oracle
memory: $b{=}11$, $c{=}1$, $p{=}0.0063$, CI $[+0.083, +0.333]$; real
vs.\ oracle context: $b{=}11$, $c{=}2$, $p{=}0.0225$, CI $[+0.043,
+0.340]$), while the oracle-versus-oracle contrast again does not
($p{=}1.0000$, CI $[-0.062, +0.104]$): evidence availability dominates
regardless of which system forms the memory.

The failure taxonomy transfers. Mem0 extracts 910 facts from 1{,}101
messages against 335 items for our rule extractor on the same questions,
and its formation recall is correspondingly higher (0.359 vs.\ 0.236).
Yet the answer-failure distribution is nearly identical to the in-house
run---\fone{} 9 vs.\ 9, \ezero{} 8 vs.\ 7, \evaluncertain{} 2 vs.\ 3,
\ffour{} 1 vs.\ 0, \fsix{} 2 vs.\ 0---and formation plus the E0 gate
again account for 17 of 22 attributable failures (77\%). The gate finds
40 sufficient, 8 insufficient, 2 uncertain; disabling it moves 6 of the
8 insufficient items into \fone{}, inflating the formation count
9$\to$15 (Appendix~\ref{app:e0}). An independent stack lands on the
same boundary structure and gate criticality.
Stage-recall \emph{levels} are not comparable across systems (content-tier
matching only, and Mem0 ships no reranker, so rerank = retrieval
identity); the label distribution is.

\section{Analysis}
\label{sec:analysis}

\paragraph{Where memory fails.}
The stage-recall chain localizes the loss upstream of retrieval:
formation recall is the lowest measured boundary, storage through
reranking sit near ceiling, and the only residual once Oracle Memory
injects gold as formed facts is context-assembly (0.951). The share is a
property of the workload: on long conversations (Study 2C, $\sim$600
messages) part of it migrates downstream (retrieval recall
1.000$\to$0.608, \ffour{} appears), while formation stays primary.

\paragraph{The oracle gap is a property of the extractor.}
On the $n{=}50$ pilot the rule extractor lets Oracle Memory beat Real
Memory by $+0.170$ ($p{=}0.0386$); under the LLM extractor the advantage
vanishes ($+0.000$). Once formation recall reaches 0.838 the oracle
condition stops discriminating: an oracle ablation on a single extractor
measures the extractor, not the architecture.

\paragraph{Reconciling with retrieval-dominant diagnoses.} A concurrent
LoCoMo diagnostic \cite{memory-probe} concludes that retrieval dominates
and write policy hardly matters. The lifecycle view predicts when each
conclusion appears: raw-storage-wins is the zero-formation-loss limit
(the null our LLM-extractor arm produces, Study 2F); retrieval-dominates
appears when retrieval methods span a wide quality range or conversations
grow long (Study 2C); write-dominance appears when extraction is the
weakest link. Locating the dominant boundary requires measuring every
boundary, not pooling one score.

\paragraph{What the E0 gate changes.}
The gate asks whether the benchmark's own reference answer is recoverable
from the gold evidence; in Study 2B 41/200 items fail it (6 more
judge-uncertain), so $\approx$24\% of the nominal error budget is
benchmark noise, not memory failure. Removing it would misattribute
those items to formation (Appendix~\ref{app:e0}); \ezero{} and
\evaluncertain{} are therefore first-class outcomes.

\paragraph{The taxonomy transfers across systems.} Mem0's OSS stack
forms 2.7$\times$ more items and reaches higher formation recall (0.359
vs.\ 0.236) on the same questions, yet its failure distribution matches
the in-house run label for label and its oracle-versus-oracle contrast
is again null: the instrument measures the lifecycle, not our code.

\section{Conclusion}

Where does long-term agent memory actually fail? The answer moves with
the formation stage: under a rule extractor the boundary sits at
formation (155/200 runs lose gold evidence before storage), an LLM
extractor relocates it downstream (the oracle advantage collapsing from
$+17.3$ points to zero, Study 2F), and an external system lands on the
same structure (Study 3A). That mobility is the transferable
contribution: \protocol{} turns a wrong answer into a lifecycle
attribution with three oracle controls, an anti-circular gate, an
adjudicated judge study, and paired statistics. The load-bearing
evidence is the stage-recall chain, which never consults the answer
judge; the answer-level gaps corroborate it but are judge-dependent---a
blind cross-family re-judge moves their levels by a few points and flips
the primary contrast on a 30-record subsample---so we report them as
supporting evidence, not the headline.

\section{Limitations}
\label{sec:limitations}

\textbf{External validity of the system under test.} Formation-boundary
numbers characterize this pipeline family, not all memory systems;
LLM-native systems with learned extraction (e.g.,
\cite{mem0,memtier,memtrace}) may locate their boundary elsewhere.
Study 3A addresses this directly: the frozen protocol, run unchanged on
Mem0's OSS stack (v2.2.1, local extractor, bge-m3 embeddings, Chroma
store), reproduces the failure-label distribution (formation and E0
again 77\% of attributable failures) and the oracle contrast structure
on the same questions, so the transferable claim is the protocol and
the boundary's extractor-dependence (Study 2F), not any single
location. The replication covers the storage stack; the extractor
\emph{model} is shared with the in-house run, and Mem0's update/delete
machinery never fires in this workload. The remaining exposure is
breadth: one external stack on
$n{=}50$ questions of one benchmark, with provenance-free artifacts
(content-tier evidence matching only) and no reranker; a broader
system sweep is future work.

\textbf{Sample size and statistical power.} Study 2B runs $n{=}200$ (both
oracle contrasts $p{\leq}0.005$); the ablations 2A/2D/2E/2F and studies
2C/3A use $n{=}10$/$n{=}50$ subsets, each with paired bootstrap CIs and
cluster-robust CIs by conversation (Appendix~\ref{app:stats}). Power
simulation for the exact McNemar rule ($\alpha{=}0.05$, 20K replicates):
at $n{=}50$ the MDE at 80\% power is $\Delta{\ge}+0.20$; the 2B
real-vs-oracle-memory contrast had 57\% power and the 3A contrast 85\%,
and reproducing the 2B effect at 80\% power needs $n{\approx}80$.
Per-type cells (Tables~\ref{tab:2b-type} and~\ref{tab:2c-type}) are
descriptive, the smaller ones exploratory.

\textbf{Judge sensitivity and self-judging.} The judge is an LLM. Study
2E measures cross-family disagreement ($\kappa{=}0.158$, gemma3:12b
over-accepts); adjudicating all 16 disagreements shifts the pilot's
numbers by $\pm$4 points without changing ordering, and two further
blind families sort by leniency rather than by noise (deepseek 13/16,
mistral 1/14 with adjudicated truth), bounding but not eliminating
adjudicator non-independence. In Study 2B the answer and judge model
coincide; the deterministic channels (including the exact-match repair)
resolve 95/191 real-memory
verdicts independently, but the judge-decided remainder inherits the
self-judging caveat. The blind cross-family re-judge quantifies the
exposure: $\kappa$ of $-0.21$ to $+0.17$ across conditions, the
Real-vs-Oracle-Memory contrast flipping sign on the
30-record subsample, and extrapolated full-sample movement large
enough to reverse the primary gap---consistent with self-preference
inflating the oracle conditions, though the alternative judge is
itself the less truth-consistent family in 2E. Remaining undecided
verdicts are few (9/14/7) and every contrast survives counting them as
wrong. All judges are LLMs; full human annotation is future work.

\textbf{Benchmark coverage.} LoCoMo categories were mapped from question
inspection and secondary docs (table ships with the artifact); benchmarks
are English conversational QA with temporal and multi-hop types
represented but not exhaustive, and the artifact is anonymized for review.

\section{Protocol Pseudocode}
\label{app:pseudocode}

The attribution decision order is frozen in \texttt{docs/PROTOCOL.md} and
implemented once in \texttt{evaluation/attribution.py}. Lexical scores are
computed for reporting only and never enter this procedure.

\begingroup\scriptsize
\begin{verbatim}
def attribute(answer, gold, ref, stages):
    v = verdict(answer, gold)
    if v == CORRECT:                  # (1)
        return NO_FAILURE
    if v == UNCERTAIN:                # (2)
        return EVAL_SEMANTIC_UNCERTAIN
    if not sufficient(gold, ref):     # (3) E0 gate
        return E0_EVIDENCE_INSUFFICIENT
    for stage in [FORMATION,          # (4) F1-F5
                  STORAGE, EVOLUTION,
                  RETRIEVAL, RERANKING]:
        if not covers(stages[stage], gold):
            return FAILURE_LABEL[stage]
    return F6_REASONING_CANDIDATE     # (5)
\end{verbatim}
\endgroup

Frozen thresholds: content-preservation check --- shared content
vocabulary $\geq 50\%$ of the smaller side and $\geq \min(2, |gold|)$
shared tokens; semantic tier --- directional containment $\geq 0.8$ with
the same absolute floor; deterministic judge support R1 --- shared span
covers $\geq 0.8$ of the candidate (verbatim-quote cases only);
deterministic judge support R2 --- pure date/relative expressions that
resolve to the same date as timestamped evidence. \verb|provenance_only|
matches are reported as diagnostics, never as stage coverage.

\section{Judge Prompts and Normalization}
\label{app:judge}

The semantic judge is prompted to decide whether the model answer is
correct \emph{given the gold evidence}, and to answer
\texttt{yes}/\texttt{no}/\texttt{uncertain} with a one-line rationale;
the judge never sees the benchmark reference answer (the E0 gate owns that
comparison) and never sees lexical scores. Two deterministic channels
repair judge output before it is accepted, both deliberately narrow:
\textbf{R1 lexical} accepts a \texttt{no} verdict only when the candidate
is essentially a verbatim quote of the evidence (shared span covers
$\geq 0.8$ of the candidate); \textbf{R2 temporal} accepts pure
date/relative expressions that resolve to the same date as timestamped
evidence. Anything wider passed wrong answers during calibration
(``went to the park'' style candidates), which is why the thresholds are
frozen and regression-tested. The cross-model judge (Study 2E) uses the
same prompt with \texttt{gemma3:12b}; agreement is reported as Cohen's
$\kappa$ on the shared subsample.

\section{Adjudication Guidelines}
\label{app:adjudication}

The 16 disagreement cases of Study 2E were adjudicated by the authors
against the gold evidence and the benchmark reference answer, under the
following written criteria, applied identically to every case and blind
to which judge produced which verdict:

\begin{enumerate}
\item \textbf{Decidable only on evidence.} A case is decidable only if
the gold evidence plus the benchmark reference answer determine the
verdict. If the reference answer is too vague to grade (two
preference-type items), the case is marked \emph{unadjudicable} and
excluded from the strict counts rather than forced.
\item \textbf{Correct iff fully supported.} An answer is correct only if
every load-bearing claim it makes is supported by the cited gold
evidence \emph{and} consistent with the reference answer. Concise,
paraphrased, and answer-equivalent forms count as correct.
\item \textbf{No unlicensed inference.} An answer that requires a step
the evidence does not license (a different entity/event assumed
identical, a superlative supported by a single item, a small arithmetic
step the reference answer does not itself make) is incorrect. Borderline
cases are labeled \emph{borderline}, not silently forced.
\item \textbf{Temporal resolution.} Relative expressions
(\emph{yesterday}, \emph{last Saturday}) resolve against evidence
timestamps before grading.
\item \textbf{Independence check.} The adjudicated verdicts were then
validated against a third judge family (DeepSeek,
\texttt{deepseek-v4.1-flash}) re-judging the same answers strictly
blind; agreement is reported in \S\ref{sec:results} and per-case
rationales are in the artifact
(\texttt{results/study2e\_judge\_gemma/adjudication\_report.txt}).
\end{enumerate}

\section{Stratification Recipes}
\label{app:stratification}

Study subsets are built by \texttt{experiments/build\_study\_set.py}.
Primary stratum: conversation (or session group) so that no single
conversation dominates and within-conversation correlation is spread
across the sample; secondary stratum: question type. Allocation is
proportional by largest remainder, with a minimum of one question per
type present in a conversation. Seed 20261018 for all studies. Committed
subsets store question-level records only; conversations are joined at
load time from the local full dataset, and raw benchmark text is not
redistributed.

\section{Statistical Procedures}
\label{app:stats}

Condition comparisons are paired by question. \textbf{Exact McNemar}: with
$b$ questions correct only under condition A and $c$ correct only under
condition B, the two-sided exact $p$-value is the binomial tail
$2\min(P(X\leq \min(b,c)), P(X\geq \max(b,c)))$ with $X\sim
\mathrm{Binomial}(b{+}c, 0.5)$ under the null. \textbf{Paired bootstrap
CI}: 10{,}000 resamples of question indices; percentile interval of the
per-question accuracy difference. \textbf{Cohen's $\kappa$}
(Study 2E): $\kappa = (p_o - p_e)/(1 - p_e)$ over the verdict categories
\texttt{correct}/\texttt{incorrect}/\texttt{uncertain}, computed on the
seeded subsample of the $n{=}50$ pilot subset that both judges re-score.
\textbf{Cluster-robust
bootstrap}. Because questions within one conversation are correlated,
condition CIs are also computed by resampling whole conversations
(clusters) rather than questions
(\texttt{paired\_stats.py --cluster-by-conversation}). LongMemEval
oracle-subset questions are sampled one per session (200 questions across
200 distinct conversations, verified), so the naive and cluster CIs
coincide there.
LoCoMo packs 50 questions into 10 conversations ($\approx$5 each); its
cluster-robust CIs are marginally wider than the naive ones (real vs.\
Oracle Memory: $\Delta{+0.200}$, naive $[+0.040,+0.360]$ vs.\ cluster
$[+0.038,+0.396]$; real vs.\ Oracle Context: $\Delta{+0.220}$, naive
$[+0.040,+0.380]$ vs.\ cluster $[+0.062,+0.408]$) but every positive
contrast survives, so the conclusions are unchanged. We report the
cluster-robust interval as the conservative bound. Study 3A reuses the
$n{=}50$ LongMemEval subset (one question per conversation), so its
naive and cluster CIs likewise coincide.

\textbf{Power and MDE.} Simulated power of the exact McNemar decision rule
(\texttt{experiments/power\_analysis.py}; discordant cells drawn from their
observed rates, 20K replicates per point, $\alpha{=}0.05$ two-sided): at
$n{=}50$, holding the false-fix rate at the observed 2\%, the minimum
detectable effect at 80\% power is a recovery rate ${\ge}21\%$
($\Delta{\ge}+0.19$; $\Delta{\ge}+0.20$--$0.23$ across the observed
false-fix range). Achieved power at the observed effects: 2B real-vs-oracle
memory ($b{=}10$, $c{=}2$, $p{=}0.0386$) 57\%, 3A real-vs-oracle memory
($b{=}11$, $c{=}1$, $p{=}0.0063$) 85\%, 3A real-vs-oracle context
($b{=}11$, $c{=}2$, $p{=}0.0225$) 67\%. Detecting the 2B effect at 80\%
power would require $n{\approx}80$; we treat the 2B contrast as significant
but modestly powered, and the smaller per-type cells as exploratory.

\paragraph{Uncertain-exclusion sensitivity (Study 2B, $n{=}200$).}
All numbers below come from \texttt{experiments/sensitivity\_analysis.py}
(no model calls; artifacts in
\texttt{results/study2b\_longmemeval\_n200\_deepseek/sensitivity.txt}).
\textbf{Exact-match repair.} The $n{=}200$ runner left 134
condition-answers unjudged whose text equals the gold answer string
(28/47/59 per condition); they carry \texttt{exact\_match}=1 and no
semantic verdict. We count them correct via a deterministic
exact-match channel---the narrowest rule in the frozen stack---giving
113/191, 143/186, 169/193. \textbf{Remaining exclusions} are 9/14/7
rows: 6/9/2 transient API errors and 3/5/5 genuine judge abstentions
(no deterministic support; the judge could not decide). Counting all
remaining exclusions as wrong: 56.5/71.5/84.5\%, Real-vs-OM $b{=}44$,
$c{=}14$, $p{=}0.0001$; Real-vs-OC $b{=}67$, $c{=}11$, $p{<}0.0001$;
OM-vs-OC $b{=}33$, $c{=}7$, $p{<}0.0001$---every contrast survives the
most conservative assignment. \textbf{Label accounting.} For real
memory the 9 undecided rows are 6 API errors (labeled
\evaluncertain{}) and 3 abstentions (unlabeled), so 84 of the 87
not-correct runs carry a protocol label (\fone{} 61, \ezero{} 10,
\evaluncertain{} 8, \fsix{} 3, \ffour{} 1, \ffive{} 1); the formation
share is 61/87 = 70\% of not-correct runs (61/84 = 73\% of labeled
failures). \textbf{Decidedness structure.}
110/200 rows are decided in all three conditions; the pre-repair
abstention tracked the shared gold evidence and judge (28 rows decided
only under Real Memory vs.\ 10 the reverse), not the condition's answer
quality.

\section{E0 Gate Ablation}
\label{app:e0}

Reviewer P5 asks what changes if a protocol component is removed. We
re-ran \texttt{attribute\_failure} on the stored Study 2B ($n{=}200$)
traces with the
anti-circular E0 evidence-sufficiency gate forced \texttt{sufficient}
(\texttt{experiments/e0\_gate\_ablation.py}; no model calls). For
real\_memory the 10 \ezero{} items---answers whose gold evidence cannot
answer the question---are re-attributed to a lifecycle stage: 9 become
\fone{} and 1 becomes \fsix{}. The formation-dominant count therefore
rises 61$\to$72 (+18\%) and the formation share among the 87 runs not
judged correct rises 70\%$\to$83\%. The gate is what prevents the protocol from conflating
question/benchmark limitations with system failures.

The same ablation on the external arm (Study 3A, Mem0, $n{=}50$)
reproduces the effect on an independent implementation: of the 8
\ezero{} items, 6 would be re-attributed to \fone{} (2 to \fsix{}),
inflating the formation count 9$\to$15 (+67\%). Gate criticality is a
property of the protocol, not of the system under test.

\section*{Responsible NLP Checklist}

\paragraph{Datasets.} LongMemEval-s \cite{longmemeval} and LoCoMo
\cite{locomo}, both publicly released for research. We use published
question-level subsets (LongMemEval-s, LongMemEval oracle subset, LoCoMo)
and join conversations at load time from the local full data; raw
benchmark text is not redistributed in the artifact (dataset versions and
licenses are recorded in the artifact manifest). Both benchmarks contain
English conversational dialogues; the subset used here contains no
multi-modal records.

\paragraph{Personal data.} Both benchmarks are synthetic or licensed
fictional dialogues; no personal data of the authors or annotators is
used. Speaker names are pseudonyms internal to the benchmarks.

\paragraph{Models and compute.} Answer models \texttt{qwen2.5:7b}
\cite{qwen25} and \texttt{gemma3:12b}, embedding model \texttt{bge-m3}
\cite{bge-m3}, all served locally via Ollama with recorded digests.
Study 2B uses \texttt{deepseek-v4.1-flash} via a commercial API gateway
(as both answer model and semantic judge, disclosed in
\S\ref{sec:results}); the blind re-judge uses \texttt{mistral:7b} and
\texttt{qwen2.5:7b}, served locally. Total
compute is single-GPU (laptop-class, 8\,GB VRAM) plus per-study API
calls; the full pipeline runs in a few hours per study.

\paragraph{Intended use and misuse.} The protocol is intended for
diagnosing memory-system failures in research settings. It is not a
leaderboard metric: attribution characterizes the concrete implementation
family under test (rule-based analyzer plus dense retrieval), and
stage-boundary numbers should not be quoted as properties of other
architectures. Automated attribution may mislabel cases where gold
evidence is ambiguous; we therefore report \ezero{} and \evaluncertain{}
separately instead of forcing a failure label.

\paragraph{Anonymization.} The public artifact will be anonymized for
review (author-identifying metadata stripped; a separate anonymous branch
is prepared by \texttt{scripts/make\_anonymous\_branch.sh}, with a
verification grep and a fresh-repo push recipe for full history
anonymization); model-server endpoints and paths are scrubbed.
