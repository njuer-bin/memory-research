# 家族 A PIP 改造设计稿（协议 v2.1 §1 落地）

**日期**：2026-10-21 深夜
**状态**：DESIGN DRAFT — 供用户拍板；生成器已实现并通过校准自测
（`experiments/kwm_pip_family_a.py --selftest`），V8/V9/V10 预跑未启动。
**范围**：仅家族 A。家族 B/C 在家族 A 通过 V8 后按同一模板复制。

---

## 1. 改造目标

把家族 A 从"教科书统计题"（MAR 缺失处理，模型可能带强先验）改造为
**实例私有信息场景**：任务成败所需的规则与历史经验逐实例随机生成，
模型权重中不可能存在（协议 §1.1 六条不可得清单），使
MUW 的 Novel(M) 由构造成立、记忆的增量价值真正可测。

保持不变：配对有效性操纵（V-dead/V-revived）、方法菜单 harness、
冻结检查点纪律、2×4→四因子格子结构。

## 2. 信息架构（三层，条件间严格控制）

| 层 | 内容 | 可见性 |
|---|---|---|
| **权重** | 统计先验（如"缺失可能导致偏倚"的一般知识） | 不可控，但**不足以**通过检查点（实例规则不在其中） |
| **README（policy v2）** | 实例私有**任务约定**：队列随机命名、signed estimand 方向、CI 水平、校准伪迹排除规则 | 全条件可见（记忆 vs NONE 比较中恒定） |
| **记忆（历史事故）** | 实例私有**失败历史**：v1 时代同步故障模式 + 实测偏倚 | NONE=空槽；UNCOND/COND/COND-MINUS 按因子注入 |

### 2.1 README 的载荷设计（V8 依据）

队列名逐实例随机（如 `cohort-kappa` / `cohort-zeta`），README 规定
**signed estimand**：`mean(ref) − mean(focal)` 及方向约定、CI 水平（95%）。
金标是**带符号**对比（N1 容差 ±0.3 绝对值）→ 无 README 的 NONE
无法知道方向，约半数实例方向错 → 成功率显著下降（V8 判据）。
该信息真实私有（随机约定），非人为刁难。

### 2.2 记忆的载荷设计（Novel(M)=1 依据）

每实例生成 v1 时代**历史数据集**（同一 DGP、同机制），实测删除法偏倚
B_hist（pp）写入记忆。记忆内容（含 θ₁、队列名、B_hist）是
**逐实例随机生成的事实**，权重中不存在（V10 审计兜底）。

## 3. 实例生成器规格（`experiments/kwm_pip_family_a.py`）

### 3.1 随机参数（全部种子落盘）

| 参数 | 分布 | 说明 |
|---|---|---|
| 队列名 | 池中抽 2 + 随机指派 ref/focal | 方向约定的载体 |
| δ_true = base_ref − base_focal | base_ref~U[9,11], base_focal = base_ref − U[1.6,2.6] | 金标（带符号） |
| θ₁ | U[0.3, 0.7] | 遗留同步故障的 z2 阈值 |
| m_hi | U[0.50, 0.70] | focal 队列 z2>θ₁ 的缺失率 |
| m_lo | U[0.06, 0.12] | focal 队列 z2≤θ₁ 及 ref 队列基础缺失率 |
| n | 2000（固定） | 与阶段 A 同量级 |
| y DGP | base_g + 0.8·z1 + 11.0·z2 + N(0,1) | c_z2=11.0 为固定仪器常数（非私有信息） |

### 3.2 有效性配对操纵（除机制外逐项匹配）

- **V-dead（遗留模式仍在）**：focal 队列 P(miss) = m_hi if z2>θ₁ else m_lo；
  ref 队列 P(miss) = m_lo。删除法偏倚目标 ≥1.0pp（N1 明确失败）。
- **V-revived（机制真被移除）**：两队列 P(miss) = 0.10 + 0.25·z1
  （与组无关、只依赖与 y 弱相关的 z1）→ 删除法目标 |dev| ≤ 0.3pp。
- 叙事：README 宣告 policy v2 移除了同步故障；V-dead 实例中
  **数据管线迁移未完成**（模式实际仍在），V-revived 中真正移除。
  区分信号在数据性质中，需分析才可得（探索可替代但耗预算——见 §5）。

### 3.3 方法与工具（冻结实现，自测口径）

- **X（naive 默认）**：dropna + 两队列均值差（README 方向）。
- **Y（mi_tool）**：模式感知插补 + 对比估计；内含**遗留模式断言**
  （检测到某队列缺失率在 z2>θ 区域集中）→ V-revived（MCAR）下断言崩溃。
  崩溃机制与阶段 A 同构：工具为 v1 时代构建，模式消失即失效。

### 3.4 检查点（必要条件式，协议 §3）

```
N1（必要）：|估计 − 金标| ≤ 0.3（绝对，带符号，README 方向）
W（加分）：CI（README 水平）宽度入带 [0.9, 3.5]（0.4）＋ 语义一致（judge，0.4）
          ＋ 工具调用 ≤10（0.2）
报告：N1 通过率（主结果）＋ W 分（次要）
```

## 4. 记忆模板（逐实例生成，事实匹配 + 长度配平）

- **UNCOND**：事故日志事实——"policy v1 时代，对本项目 {dir} 队列对比做
  完整记录（删除）分析，因同步故障丢弃 {g\*} 队列 z2>{θ₁} 的记录，
  偏倚实测 {B_hist}pp。勿在本项目依赖删除法做队列对比。"
- **COND** = UNCOND + 适用条件："此教训成立于 policy v1 的同步故障模式
  （缺失集中于 {g\*}、z2>{θ₁}）。若当前数据已无该模式，删除法未必有偏——
  采纳前先核实当前缺失机制。"
- **COND-MINUS** = UNCOND 的适用句替换为等长中性档案填充
  （治理会议纪要、归档编号等）。
- 污染校验：模板不含金标数值；COND vs COND-MINUS 嵌入距离 < 0.5（启发式）
  **加人工盲评**（V10）；长度配平 ≤10%。

## 5. 探索替代性控制（六条不可得清单第 4 条的操作化）

私有规则不可从工具行为**廉价**反推：检测当前缺失模式需
按队列 × z2 区域做缺失率分析（INSPECT 类动作），消耗调用预算；
记忆直接给出该诊断。**校准目标**：NONE × budget=3 的 V-dead 成功率
应显著低于 MEMORY 条件（记忆有增量），但 NONE × budget=3 ≠ 0
（任务非不可完成，排除"任务坏了"解释）。若预跑发现 NONE+探索
≈ MEMORY，则信息被探索完全替代 → 回炉（提高诊断成本或降低预算）。

## 6. Harness 变更：方法菜单增加 INSPECT 动作（v2.1-harness）

阶段 A 教训（§7.4-5：前瞻性条件使用必须结构性引出）：
budget=1 的纯 METHOD 菜单使 COND 的"先核实再采纳"**结构性不可测**。

```
动作集：METHOD: <name>（消耗唯一方法承诺）
        INSPECT: <analysis-op>（不消耗方法承诺；消耗调用预算 ≤10）
        FINAL: <answer>
```

INSPECT 仅提供读数类分析（缺失率切片、描述统计），不给结论。
承诺次数（budget ∈ {1,3}）与调用预算（≤10）分别计量——F4 只操纵前者。

## 7. V8/V9/V10 预检设计（本设计稿的验收门）

| 门 | 设计 | 通过判据 |
|---|---|---|
| **V8 Novelty control** | NONE×无README vs NONE×有README，budget=3，n≥3/格 | 前者 N1 通过率显著更低（方向翻转 ~50% 由私有约定导致） |
| **V9 Actionability control** | 记忆内容明确正确且适用无歧义（如"本项目对比方向为 ref−focal，采用 README 约定"） | 模型按记忆行动的比例 ≥ 预设门槛；失败 → 换模型，不跑主矩阵 |
| **V10 泄漏审计** | ①生成器静态断言：任务描述/README/工具名不含 θ₁、B_hist、金标、方向以外的队列语义；②模板盲评（人工 ≥2 人）确认 COND-MINUS 不含适用条件语义；③种子/历史/变更记录留存为工件 | 全绿才可进确认性阶段 |

## 8. 与四因子的映射

F1 Novelty：NONE（空槽）/ MEMORY（PIP 事故记忆）——记忆为私有信息唯一载体；
F2 Validity：§3.2 配对构造；F3 Type：§4 三模板；F4 Budget ∈ {1,3}。
16 格 × 实例 × 模型 × 种子；主终点 = N1 通过率。
