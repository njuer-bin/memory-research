# KWM 协议 v2.1（草案）：无混杂的下一轮实验（任务私有信息场景）

**日期**：2026-10-21 深夜
**状态**：DRAFT — 按第二轮/第三轮外部评审行动起草，v2.1 吸收第四轮评审的
四因子设计与形式化假设；**关键参数待用户拍板后冻结**，冻结前不启动任何正式 run。
**定位**：这是 MUW（Memory Utility Window，原 H-window）假设的检验实验设计，
不是对阶段 A 仪器的否定。阶段 A 仪器（模拟器/工具/污染校验/记忆层）作为
基础设施复用，任务信息内容与提示结构按本协议重建。

## 0. 形式化假设与测量链（第四轮评审引入；第五轮评审降级理论强度）

**Memory Utility Window（MUW）— 信息通道上的*候选*窗口，非完整必要条件理论**：
对检索记忆 M 与智能体 A，ΔU(M) = U(A|M) − U(A|∅)。我们假设记忆经**信息通道**
产生决策增益（ΔU>0）仅当两个潜在属性同时成立：

- **Novel(M)**：记忆承载的经验**不在**模型权重中（就该通道而言否则冗余）；
- **Actionable(M)**：智能体**能够**按记忆指示行动（否则惰性）。

|  | Actionable | Not actionable |
|---|---|---|
| **Novel** | *utility window*（ΔU>0 可能） | inert |
| **Known** | redundant（就信息通道） | inert |

**理论边界（第五轮评审，必须随预注册冻结）**：已知 lesson 的记忆仍可经与
novelty 正交的通道产生价值——provenance、置信度校准、显式证据、时间有效性边界、
检索接地、不确定性降低、决策时显著性——故 Novel(M)=0 **不**蕴含 ΔU=0。
本协议只检验**实例级信息**通道（记忆是否携带权重与任务面都不具备的决策相关信息）；
PIP 设计使该通道成为唯一可用通道，因此本设计下的零效应只针对该通道说话，
不推广到记忆效用的一般理论，也不触及上述正交通道（列 future work）。

**测量链（三层各有测量，不许互相替代）**：

```
L1 可用性：memory_injected / retrieved / quoted   （usage measure）
      ↓
L2 机制：method_adopted（method adoption = mechanism measure）
      ↓
L3 结果：N1 必要条件通过率（Task Success = 唯一主要终点）
```

主实验只检验 ΔU（L3）；L2 是机制测量、L1 是使用测量，均只作描述与中介解释，
**不作为主要终点的替代**（阶段 A 教训：行为层停机 ≠ 主要终点已检验）。

## 0.5 设计目标（对应历轮评审）

1. **无混杂**：所有条件共用同一基础提示词；记忆载荷是条件间唯一差异。
2. **终点分离**：L3 任务成功是唯一主要终点；行为层只设预注册**停机门槛**
   （G-core'），且 G-core' 的失败只授权停机，不得表述为"主要终点已检验为阴性"。
3. **任务私有信息**：逐实例随机生成模型权重中不可能存在的信息，使 NONE 条件
   无法靠先验知识通过检查点——把 Novel(M) 从"推断"变为"构造成立"。

## 1. 任务域重建：任务私有参数（PIP, project-private information）

### 1.1 构造原则

每个任务实例携带一组**逐实例随机生成**的项目规则/环境参数（种子落盘、可复现），
例如（家族 A 的改造示例，最终以冻结文档为准）：

- 缺失机制由实例种子决定（MAR-by-z1 / MAR-by-(group,z2) / MNAR-margin 三选一，
  参数随机）——**先验的教科书规则不再充分**，因为"哪种缺失机制、哪个变量驱动"
  是项目私有的；
- 唯一可信信息源 = 项目 README（会话内可见的合成项目文档）或失败记忆；
- 金标由模拟器按实例种子直接计算，检查点容差沿用冻结绝对值口径（必要条件化，
  见 §3）。

**实例私有信息的六条不可得清单（第五轮评审；V10 审计逐条核验）**——私有规则：
1. 不存在于模型训练数据（随机生成，非教科书先验）；
2. 不存在于 system prompt 或任务描述；
3. 不存在于工具名称或工具接口签名；
4. 不可从工具行为反推（探索只能发现"什么有效"，不能直接得到规则内容——
   若探索可在预算内完全替代记忆，则该信息不合格，须回炉）；
5. 只存在于记忆或环境状态（README / 会话状态）中；
6. 与金标的推导关系唯一（给定规则 → 唯一正确输出，避免规则-金标多解）。

### 1.2 关键预检（V8/V9/V10 门，全部通过前不得进入确认性阶段）

**V8 = Novelty control（权重缺席验证，MUW 前提 Novel(M) 的独立测量）**：
NONE 条件 × 无 README × 允许自由探索的小样本预跑（n≥3），
任务成功率必须显著低于有 README 的 NONE 条件——即证明该信息确实不在权重里。
V8 不过 → 任务域不合格，换信息类型，不得进入确认性阶段。

**V9 = Actionability control（记忆使用正对照，第三轮评审新增——MUW 前提
Actionable(M) 的独立测量）**：
单独条件——记忆内容明确正确、适用性无歧义、与当前任务直接相关——检验模型能否
执行记忆建议。若模型连此条件都无法利用记忆，主实验的零效应**不得**解释为
"记忆缺乏增量价值"（失效在记忆使用，不在记忆内容）。V9 失败 → 换模型或先解决
记忆使用问题，不跑主矩阵。

**V10 信息不可获得性与泄漏审计（Novel(M) 构造成立的兜底验证）**：
- 每实例随机生成参数的种子、历史环境、变更记录全部留存为工件；
- 任务描述与工具接口审计：实例级答案不得经题目描述或固定工具名泄漏/可推；
- COND-MINUS 模板盲评（人工）替代单一嵌入距离判定（嵌入距离只是启发式）。

## 1.5 因子结构（四因子，第四轮评审定稿）

| 因子 | 水平 | 说明 |
|---|---|---|
| **F1 信息新颖性 (Novelty)** | NONE / MEMORY | NONE=空记忆槽（结构同提示）；MEMORY=记忆承载实例私有规则。MEMORY 条件下记忆是私有信息**唯一**载体，Novel(M) 由构造成立（V10 审计兜底） |
| **F2 记忆有效性 (Validity)** | DEAD / REVIVED | 沿用阶段 A 配对操纵；REVIVED 下旧路径重新可行 |
| **F3 记忆类型 (Type)** | UNCOND / COND / COND-MINUS | 仅在 MEMORY 水平内有意义；模板事实匹配+长度配平（V4） |
| **F4 尝试预算 (Budget)** | 1 / 3 | 阶段 A 观察到预算↔切换的对应关系，本轮作为预注册独立因素交叉检验 |

**格子数（每模型 × 每实例集）**：
NONE：2 变体 × 2 预算 = **4 格**；MEMORY：3 类型 × 2 变体 × 2 预算 = **12 格**；
合计 **16 格**；另有 V9 正对照（独立条件，不计入主矩阵）。

**方向性预期（预注册，均落在 L3）**：
- V-dead：MEMORY(UNCOND) vs NONE ↑（记忆帮助避免重复失败）；COND ≈ UNCOND；
- V-revived：MEMORY(UNCOND) vs NONE ↓（错误放弃）；COND 恢复至 ≥NONE；
  **COND-MINUS 恢复失败（≈UNCOND）**——COND vs COND-MINUS 差 = 适用条件信息的
  净效应（H-C 确认性检验）；
- Budget 仅作机制探索假设（预注册但降级为次要），不作确认性主张来源。

## 2. 无混杂提示结构

所有条件（含 NONE）收到**结构相同**的提示：

```
[任务描述]（逐字相同）
[记忆槽]  NONE: "本项目暂无历史经验记录。"
          UNCOND/COND/COND-MINUS: 注入对应模板（事实匹配、长度配平，沿用 V4 校验）
[使用规则]（逐字相同，全部条件渲染）：
  "若记忆槽含历史经验记录，请自行判断其是否适用于当前数据，再决定是否采纳。"
```

- 记忆内容 = 条件间唯一差异；使用规则对全条件一致 → §4.4 混杂消除。
- 若研究问题改为"记忆+规则的组合效应"，须作为显式处理因素写进预注册
  （2×2：有无规则 × 记忆类型），不得事后归因于单一因素。

## 3. 指标重构：必要条件式 L3（修冻结权重底分缺陷）

阶段 A 的 0.4·s1+0.2·s4 即达 0.6 的底分缺陷（无 CI、无语义分也可 pass）在
v2.1 中以**必要条件**结构修复（评审问题 4 的落实）：

```
任务成功 = 必要条件 AND 加分项
  必要条件 N1：主估计落入冻结容差（家族 A：|Δ−gold| ≤ 0.3，逐实例金标）
  加分项 W：CI 报告且宽度入带（0.4）＋ 语义一致（judge，0.4）＋ 工具调用 ≤10（0.2）
  报告：N1 通过率（主结果）＋ W 加权分（次要结果）
```

- **语义 judge 在确认性阶段开始前建成并通过测试集**（人工标注 ≥30 条结论、
  judge 与人工一致率 ≥90% 方可解锁）；不再允许"judge 未建 → unjudgeable"
  进入确认性结果。
- **评分字段自测前置（第三轮评审新增）**：自动化测试证明**每一种允许的方法**
  都能产出评分协议所需的全部字段（如 CI）；无法产出者，其缺失字段处理方式必须
  在预注册文本中事先规定——不允许确认性阶段出现"结构性不可达的检查点"
  （阶段 A 家族 A mi_tool 无 CI 的教训）。
- 冻结后按预注册分析，不得看结果后调整。

## 4. 终点与停机门槛的正式分离（写进预注册文本）

- **主要终点（唯一确认性主张来源）**：L3 = N1 必要条件通过率（Task Success），
  §1.5 四因子 16 格各格 ≥5 独立任务实例（实例为随机效应），≥2 模型 × 2 种子。
  方向性预期见 §1.5（H-A/H-B/H-C 沿用并落到 MEMORY/NONE 与 COND/COND-MINUS
  对比上）。
- **G-core'（停机门槛，非主要终点）**：L2 行为层（method_adopted）在 MEMORY
  vs NONE 上出现任何跨变体方向性差异 → 继续；否则按预注册停机。**G-core' 失败
  的报告措辞固定为："确认性试点触发预注册行为层停机条件；主要终点未被完整
  检验。"**
- 判定层级（L1→L2→L3 各层独立测量、不互相替代）：G-core'（L2 viability，
  仅停机决定）→ 主要终点（L3/N1）→ 次要（W 分）→ L2 method adoption 机制
  描述 → L1 retrieval/quotation 使用描述。任何 L1/L2 层发现**不得**写为主要
  结论。

## 5. 执行与留痕纪律（阶段 A 三项血缘缺陷的整改前置）

1. run JSON 强制字段：`model`、`harness_version`、`seed`、`instance_id`、
   `methods_tried[]`、`method_adopted`、完整 OBSERVATION payload；
2. 结果 tag 命名空间 = `{family}_{variant}_{condition}_{model}_{rep}`，禁止复用；
3. 全部运行日志当天入库 `results/.../logs/`（阶段 A 两条"不可验证"行即因此）；
4. 检查点自测套件：冻结实现 × 已知输入 → 期望输出，确认性阶段前全绿；
5. 预注册文本（本协议冻结版）在任何确认性 run 之前 commit + push。

## 6. 规模与预算（待拍板参数）

按 §1.5 四因子 16 格计（每模型 × 每实例集）：

| 参数 | 建议值 | 说明 |
|---|---|---|
| 实例/格 | ≥5 | 随机效应的最小可辩护规模；功效分析在家族 A 改造完成、V8 通过后补 |
| 模型 | 2 | 模型为测量因素（非"能力层级"——阶段 A 教训：无独立能力测试不设层级）；全因子交叉 |
| 种子/格 | 2 | 稳定性 |
| **F4 尝试预算** | ∈ {1, 3}，预注册独立因子 | 已入 §1.5 因子结构（第三轮评审要求） |
| 总 run 数 | ≈ 16 格 × 5 实例 × 2 模型 × 2 种子 = **160** + V9 正对照 ≈ 20 | 分批执行，每批后按预注册无 peeking 规则处理 |

## 7. 明确不做的事

- 不用本协议数据回填阶段 A 叙事；阶段 A 记录保持冻结 + 勘误制。
- 不在 V8（权重缺席）、V9（记忆使用正对照）、V10（泄漏审计）全部通过前启动
  任何正式 run。
- 不把探索性预跑的观察并入确认性统计（各跑各的、口径分开）。
- 本协议在冻结并 commit 预注册之前，对外/对文档一律称 **"proposed confirmatory
  protocol (draft)"**，不得表述为已预注册（第三轮评审）。
