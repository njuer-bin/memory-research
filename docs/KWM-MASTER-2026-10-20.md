### 1.2 v2.0 新核实：两篇近邻工作（2026-10-21 逐篇核对）

外部评审指出两篇 v1.0 检索遗漏的近邻工作。核实结论：

**① Beyond Memory: A Templated Substrate for Heterogeneous Collaborative Knowledge
Work with LLM Agents**（arXiv:2607.24759，Moreira & Sweet，Notre Dame，2026-05-29）
- 做了什么：`llm-wiki-memory-template`——agent 维护的 append-only wiki，插入原始资料与
  agent 之间；以 append-only 约定保留死径、被撤回主张、被审计下调的数字；提出三轴设计
  框架（multi-human / multi-agent / multi-domain）。
- **性质：设计 + 案例研究论文**（3 个部署案例 + 1 份设计报告），含一个追溯审计案例
  （20/20 覆盖声称被审计修正为 14 和 12）。
- **没有**：受控实验、内容类型消融、帮助-有害测量、统计检验。
- **重叠层次：动机层**——"知识工作会丢负面结果、失败路径值得保留"这一动机与我们高度
  重叠，但其贡献是模板与社会技术性质，不是测量。

**② Negative Knowledge as Failure-aware Shared Memory for AutoResearch**
（arXiv:2606.21024，Hanchun Wang，2026-06-19，代码开源）
- 做了什么：curator agent 把每次失败尝试转成 bounded、typed record 存入共享库；
  下游科研 agent 在提出下一实验前**显式 adopt 或 reject** 这些记录。
- **已经做了受控内容注入比较**（这是 v1.0"无人做内容级控制实验"说法被推翻的直接原因）：
  - ScienceAgentBench 同任务重试：baseline/vanilla retry 31.6% → 单条负面记录 36.8%
    （296 token，比 self-debug 省 73.3%）→ 三轮压缩深度记录 47.4%（超三轮 self-debug
    的 44.7%，token 再省 28.3%）。
  - PDE 跨任务：库 58 条（15 正 43 负）；四条件 **Base 0/3、Base+Pos 1/3、Base+Neg 3/3、
    Base+Pos+Neg 3/3**；跨系统迁移 BKdV→BNLS：无库 0/4、有库 2/4。
  - trace 分析：agent 依据负面记录改单组件、显式否决两条备选路线。
- **没有**：token-matched 内容对照（其 token 比较对象是 self-debug，不是等量无关记忆）、
  帮助-有害权衡、阶段敏感性、适用边界/负迁移测量、oracle 分离（检索 vs 使用）、
  任务级统计功效（仅 3 个测试任务、单作者、Claude Sonnet 单模型族）。
- **一个对我们有利的事实**：Base+Pos 在 2/3 任务上失败而 Base+Neg 全过——正面经验
  跨问题迁移反而误导。这是"记忆可以有害"现象的意外旁证，说明我们的核心假设可检验。

### 1.4 v2.1 新核实：三篇竞争工作（2026-10-21 第二轮，逐篇核对摘要 + 正文要点）

> 触发：第二轮外部评审指出"记忆有害/负迁移本身已不能作为充分新颖性"。以下三篇全部
> 核实属实，直接影响 v2.0 的空白判断与主张落点。

**① Xiong et al., ACL 2026 Long（2505.16067 / 2026.acl-long.27，Harvard/UMN/MSU/UGA）**
《How Memory Management Impacts LLM Agents: An Empirical Study of Experience-Following Behavior》
- 实证研究 memory addition/deletion 操作；发现 **experience-following 特性**：任务输入与
  检索记录输入高度相似 → 输出高度相似（"复制粘贴陷阱"）。两大挑战：**error propagation**
  （错误经验复利恶化）与 **misaligned experience replay**（过时/无关经验负向影响当前任务，
  即"看似正确的历史经验也会误导"）。缓解 = 选择性添加 + history-based 删除（平均 +10%）。
- 4 类 agent（RegAgent 合成、EHRAgent、AgentDriver、CIC-IoT）。
- **重叠评估**：现象层重叠最重——"旧经验造成负迁移"已被它说了。但机制上是**情景记录
  （query, output）的输入相似性模仿**，不是提纯的失败知识；操纵的是增删操作与质量筛选，
  不是记忆的**表征形式**；task distribution shift 只做鲁棒性观察，没有 dead/revived 式
  **配对有效性操纵**；没有条件化表示干预；场景非知识工作。
- **定位**：既是空白修正对象，也是**机制层竞争解释**——我们的负迁移发现必须回答
  "是否只是 experience-following 的另一例"（→ §13 新增机制竞争检验）。

**② Remember When It Matters（2607.08716，Meta AI，2026-07-09）**
- 独立记忆 agent 与执行 agent 并行，决定**是否注入**记忆 grounded 提醒（"behavioral
  state decay"）；selective intervention 优于被动暴露/always-on/advisor-only/general
  retrieval；Terminal-Bench 2.0 +8.3pp、τ²-Bench +6.8pp；另训练 Qwen3.5-27B 策略。
- **重叠评估**：方法层占位——若我们的方法贡献落成"判断这条记忆现在该不该被调用"，
  会与其直接撞车。但其干预时机决策基于一般相关性，**不操纵记忆表征形式**（无条件 vs
  条件化），**不操纵环境有效性**（dead/revived），无失败经验适用边界测量。
- **定位**：相关方法，须引用并对比；我们的方法贡献若成立，是"改记忆怎么写"而非
  "改注入时机"，与其正交；写作时明确两者可组合。

**③ MeClear（2609.09115，2026-09-08）**
- 任务条件化记忆清除：LOO 筛选 + 采样 Shapley 合作归因识别**对当前任务有负效用**的
  记忆，查询级最小清除（可逆，不改库）；LoCoMo 长对话 + 故障注入，745 案例，
  task recovery 82.3% vs LOO 56.8%。
- **重叠评估**："发现有害记忆并降低其负面作用"已是活跃方向。但其单位是**查询时刻的
  单条/联合记录效用**（对话 QA、注入故障），不是**失败经验的任务级适用性**；处理手段
  是压制（clearance），不是重新表征（conditionalization）；无有效性操纵、无行为层
  （放弃/探索）测量。附带影响：其操作级归因方法与论文一（证据级生命周期归因）存在
  表面相近，论文一 related work 需一并差异化。
- **定位**：相邻但不同层；引用并对比"压制 vs 条件化重表征"。

**小结（v2.1 空白再修正，v2.2 再修订见 §1.5）**：至此已被占的主张——"记住失败经验有用"（2606.21024）、
"记忆可传播错误/造成负迁移"（ACL 2026）、"识别并清除有害记忆"（MeClear）、
"决定何时注入记忆"（2607.08716）、"边界/条件化表示有因果作用"（BASM，§1.5）。
**仍然无人做的**：①失败经验适用性的**受控操纵**
（同一死径 dead vs revived 配对）＋效应反转测量；②以**实际失败的实验路径及失败原因**
为记忆对象的测量研究（BASM 对象是成功技能）；③边界信息的**代价面**——错误放弃与
探索抑制（BASM 及各近邻只测收益）；④知识工作域的复现。v2.2 主线即锚定这四点（§3.1）。

### 1.5 v2.2 新核实：BASM（2026-10-21，读摘要页 + HTML 正文）

**When Not to Imitate: Boundary-Aware Skill Memory for Reliable Tool-Use LLM Agents**
（2608.22339，Meituan + CASIA，2026-08-23，**EMNLP 2026 Findings 已接收**）

- **现象**：Skill Imitation Trap——从成功轨迹蒸馏的技能记忆，在"语义相似但实际不适用"
  的任务上，检索越多技能反而越自信地调错工具（procedure skills 使 wrong-tool margin
  比 memory-free 基线高 47%）。
- **方法**：每条技能增配四个边界字段——**applicability conditions / risk cues /
  avoidance rules / recovery notes**，把无条件动作模板变成 state-conditioned guidance
  （条件成立才应用、不成立则抑制、失败则定向修复）。
- **机制分析（与我们 H-C 同型）**：attention 分析显示 success-distilled 记忆把注意力
  转向程序内容、忽略边界线索；**same-prompt knockout 阻断 boundary-span attention
  可恢复 69.4% 的模仿陷阱效应**——边界字段被证明为因果性反模仿通道。
- **结果**：AppWorld 成功率 +23.8%、BFCL +5.0%、AgentDojo 攻击成功率 −4.6%，
  4 个模型规模，3 个 benchmark。

**重叠评估（v2.2 新颖性边界再修正）**：评审指出正确——以下三条**不能再作为创新点**：
①"旧经验缺少适用条件会产生负面影响"（其 Skill Imitation Trap + 2605.12978 的
"抽象丢失适用条件→过度泛化干扰"均已观察）；②"显式适用条件可能改善迁移"（其核心
贡献，且做了消融+机制分析）；③"执行时检查适用条件可能降低错误行动"（其 recovery
notes + decision-time checking 已覆盖）。其 knockout 分析甚至与我们 H-C 的机制
分离思路同型，必须作为机制层最强近邻对待。

**仍可辩护的区别（候选差异，非已证明的创新）**：

| 维度 | BASM | 本研究 |
|---|---|---|
| 经验对象 | **成功技能**（失败轨迹仅作边界线索/修复来源） | **实际失败的实验路径 + 失败原因**本身作为记忆对象 |
| 核心问题 | 给技能附加边界、减少错误模仿 | **同一条失败经验在环境改变后从有用约束变成错误禁忌**的条件 |
| 有效性操纵 | 无配对操纵——"不适用状态"是跨任务构造（需不同工具的相似任务） | **家族内配对 V-dead/V-revived**，同一死径的当前有效性被直接翻转 |
| 效应测量 | 只测收益（抑制错误调用、成功率↑） | **双面测量**：重复死径（收益）与**错误放弃/探索抑制**（代价）|
| 结果可能方向 | 边界信息总是有益 | 边界信息**可能有害**（过度抑制可行路径）——阴性/反转均可发表 |
| 场景 | 工具使用/API benchmark | 长程知识工作 ≥2 域 |

**v2.2 主线重述**：不是"提出条件化记忆"（BASM 已做），而是**用配对有效性操纵测量
边界信息在失败经验上的收益-代价权衡**——尤其回答："当过去失败的路径在新环境中重新
变得可行时，什么信息能帮助智能体正确修正旧经验，而不是机械服从或彻底遗忘？"
BASM 从未测量过边界信息导致**错误放弃**的情形——这正是本研究与其互补的接缝。

### 1.6 阶段 0 候选近邻（2026-10-21 检索识别，**2026-10-21 已读全文审计完毕**）

### 2.4 Consolidation Audit 定位与研究问题（已作废）

## 3. 主线定位（v2.0）：When Does Memory Help or Harm Long-Horizon Knowledge Work?

### 3.1 核心研究问题（v2.2 最终收窄）

**当过去失败的路径在新环境中重新变得可行时，什么信息能够帮助智能体正确修正旧经验，
而不是机械地服从（错误放弃）或彻底遗忘（重复踩坑）？**

（v2.1"适用边界与条件化使用"再收窄：BASM（§1.5）已证明"给技能加显式边界有因果
作用"并做了机制分析，故**条件化表示本身不是本文创新**；本文贡献是——以**配对有效性
操纵**（同一条失败经验 dead vs revived）测量边界信息在**失败经验**（而非成功技能）
上的**收益-代价权衡**，包括 BASM 从未测量的代价面：边界信息导致错误放弃。宽问题
"when does memory help or harm" 仍是背景框架；v1.0 内容分类学仍是第一阶段手段。）

### 3.2 核心科学假设与判定规则（预注册，v2.2 强化判定纪律）

**假设**：失败经验的决策效应取决于其**适用性结构**——旧路径在当前环境中是否仍然
失效，以及记忆是否携带该适用性信息。

- **H-A（适用边界反转，核心假设；v2.3 主结果指标统一）**：失败记忆的效应方向随环境
  有效性反转。**主要结果指标（primary outcome）= 任务成功率**（或预注册的加权
  正确决策得分），同一指标在两个环境中的方向性预期分环境预注册：
  | 对比 | 预期主结果 |
  |---|---|
  | V-dead：UNCOND vs NONE | 成功率提高 |
  | V-revived：UNCOND vs NONE | 成功率下降 |
  | 两环境差异 | 支持预注册方向的效应反转 |
  重复死径率与错误放弃率是**两个不同的 L2 行为指标**，作为解释主结果为何变化的
  次级读数，不与成功率拼成统计交互（v2.3 修正）。
- **H-B（条件化缓解；v2.2 重述 + v2.3 界值时点纪律）**：COND 相对 UNCOND 在
  V-revived 中显著减少对主结果的损害（方向性检验）；**且**在 V-dead 中主结果不低
  于 UNCOND 超过**预注册非劣效界值 δ**。**δ 时点纪律（v2.3）**：δ 在确认性实验
  （阶段 B）开始前，按"可接受的实际损失与研究目标"确定并冻结；阶段 A 只用于估计
  方差与规划样本量，**不得**作为看完结果后选择易通过界值的依据。
  "差异未达统计显著"不构成无伤害证据，必须用非劣效检验。H-B 是**测量**边界信息
  在失败经验上的因果作用（BASM 未测此对象与代价面），不是提出条件化记忆方法。
- **H-C（v2.3 表述收窄）**：**在控制文本长度与一般性附加内容后，显式适用条件是否
  比非诊断性替代内容带来额外收益？** 等长 COND-MINUS 对照能排除"优势来自文本长度
  或一般性附加文本"，**不能**排除"COND 提供了更多任务相关信息"——适用条件本身就是
  有决策价值的信息，不可能既保留其决策信息又删除它。论文中不宣称"条件信念"与
  "更多信息"被彻底分离。**附：UNCOND 隐含条件预试验（v2.3 新增）**——UNCOND 中的
  失败事实可能已隐含适用条件（如"16GB 显存下 OOM"提示资源约束），预试验检查模型
  能否从 UNCOND 推断出条件；若能，本研究测量的即"显式标注边界的增量价值 vs 让
  智能体自行从原始失败事实推断"——同样有意义，但必须在论文中如此表述。
  机制层对话（experience-following 模仿与 BASM boundary-attention 通道是否反向
  工作为过度抑制）见 §13.8 机制竞争检验，作为 H-C 的解释性配套而非独立假设。
- **H-D（阶段敏感性，v2.0 的 H1，降为次级分析）**：FAIL 记忆在延续/执行期减少无效
  重复；探索期效果不同。作为解释性次级分析报告，不承担主假设。
- **H-E（因果分离，v2.0 的 H3，降为试点验证）**：oracle 注入差值可按 §17.2 判读
  归因——仅在阶段 A 试点中验证其必要性（§11.4 减法表），不贯穿所有条件。

这是待验证假设，不是既定事实；支持或反驳，只要设计能区分解释，都有发表价值
（含阴性结果：条件化在失败经验上不缓解、或边界信息在两种变体中同向 → 对 BASM
结论在失败经验对象上的边界条件，仍可发表）。

### 3.3 三阶段研究结构（v2.1 重排：适用边界升为第一主战场）

1. **研究适用边界（主战场）**：**2×4 主实验**——{V-dead, V-revived} × {NONE, UNCOND,
   COND, COND-MINUS}（→ §9.2 核心设计、§11.4 减法表），测效应反转与条件化缓解；
   COND+CHECK 为独立方法实验，不进主设计（v2.3 统一，清除版本矛盾）。
2. **建立因果证据（基线骨架）**：同一任务、同一模型、受控预算下的关键基线
   NONE / token-matched / random-irrelevant（→ §11.1），排除信息量与任意文本混淆。
3. **解释行为机制（机制层）**：L1/L2/L3 三层测量（→ §17）+ 机制竞争检验（H-C，
   对话 experience-following 解释）；oracle 分解只在试点中验证必要性。

三个优点（采纳评审归纳）：分类学降为实验手段而非全部创新；"形式干预 → 行为变化 →
结果变化"串成因果链；允许有价值的阴性结果。

# 第二部分：实验设计（v2.0）

## 7. 一句话设计

同一批长程知识工作轨迹、同一份冻结抽取结果，在**检索/上下文组装层**按决策功能做
受控注入与移除（完整对照阶梯见 §11），用**确定性检查点 + 行为信号**测量记忆对后续
决策的帮助与伤害。主线问题不是"哪类记忆有用"，而是**"记忆何时帮助、何时有害"**。

关键隔离：抽取只做一次并冻结，消融不碰抽取器；分析单位是**任务**，不是检查点。

## 8. 构念定义：决策功能分类学（v2.0 修正）

类别由**条目在决策中的功能**定义，不由语法形式定义（区别于 Mem0/Letta 的存储类型
`fact/event/relation/rule`）。

| 代码 | 决策功能 | 定义 | 正例 | 反例（易混） |
|---|---|---|---|---|
| FACT | 提供世界状态 | 关于数据/工具/文献的静态陈述 | "数据集有 12,408 行、缺失率 3.2%" | "上周发现缺失率 3.2%"（事件） |
| PROC | 提供可执行方法 | 可复用工作流/工具序列 | "复现前先跑 `validate.py --strict`" | "我跑了 validate.py"（一次性事件） |
| FAIL | 提供负面约束 | 试过且失败的路径 + 原因 + 证据 | "调大 lr 到 1e-3 会发散；10 步内 NaN" | "lr 是 1e-4"（事实，无失败信息） |
| LINEAGE | 提供演化状态 | 假设提出→修正→否证链，带理由与时间 | "假设 H2 在 3 月被周聚合数据否证，转向 H3" | "当前假设是 H3"（事实，丢链条） |
| CONSTRAINT | 提供可行性边界 | 预算/时间/环境/前提限制 | "显存 16GB，batch>32 OOM" | "用了 batch=32"（一次性选择） |

### 8.1 实现方式

- 不改存储 schema：`metadata.kwm_category` 字段 + 检索层 category filter
  （`hybrid_retriever.py` 的 `memory_types` filter 先例）。
- 打标：(a) 抽取器 prompt 打标（主路）；(b) 人工标注 10–15% 子集校准（沿用论文一
  judge 校准门槛，报告一致性）。

### 8.2 为什么这五类（降为论证，不是主张）

用户 6 大用途映射：检索召回（全部）→ 规划/procedural（PROC）→ 一致性画像（不测）
→ 反思自校正（FAIL/LINEAGE）→ 记忆库维护（不在本期）→ 评估 Debug（检查点即仪器）。
**v2.0 定位：五分类是实验仪器，不是论文贡献**——论文主张的是条件结构（§3.2），
五分类被证伪时研究仍成立。

### 8.3 多重标签处理（v2.0 新增，回应评审第 3 条）

混合条目真实存在（如"lr=1e-3 出现 NaN；当前显存预算下应优先尝试 1e-4"同时含失败
教训 + 约束 + 程序建议）。处理规则（进 codebook 并冻结）：

- **主功能单标签**（用于过滤消融）：按裁决规则定主功能。候选规则（冻结前定稿）：
  含"已尝试且失败"的因果信息 → FAIL 优先；否则按决策时刻最可能被使用的功能。
- **全标签记录**（用于描述性分析）：每条目的全部适用标签入库，供跨类重叠率分析。
- **标注者一致性**：双人独立标注子集，报告 Kappa；低于门槛先修 codebook 再全量打标。
- **敏感性分析**：主功能裁决规则换用替代规则重跑关键比较，结论须稳健。

## 9. 任务集：可验证检查点（checkpoint）

每个任务是一串阶段，每阶段有外部、确定性可判的通过条件。检查点规格跑分前冻结；
agent 看不到检查点文本。

### 9.1 三类任务原型（v1.0 保留）

**T1 数据分析复现**：C1 清洗后规模（精确）；C2 主指标（预注册容差，默认 ≤1%）；
C3 分组/方向符号；C4 结论与数据一致（语义判分，见第 10 章）。

**T2 记忆恢复续做**：前段自由探索（产生真实死径与假设转向），后段清空会话凭记忆续做。
C5 不重复已失败路径（检测规则冻结：字符串 + 参数区间双重匹配）；C6 续做起点正确；
C7 关键前提未违反。

**T3 文献综合**：C8 应引覆盖率（必引集合来自任务描述）；C9 无幻觉引用（溯源用
`PROTOCOL.md` §4 同款内容保存校验）；C10 定位陈述正确（语义判分）。

### 9.2 核心实验：适用性 × 表征形式 2×4 主实验 + 独立方法实验（v2.3 最终统一）

> **v2.3 统一（采纳第四轮评审，清除版本矛盾）**：**主实验 = 2×4**——
> 环境有效性 {V-dead, V-revived} × 记忆条件 {NONE, UNCOND, COND, COND-MINUS}；
> **COND+CHECK 为独立方法实验**，与主实验分开报告。主实验因此只有一组清晰的
> 确认性假设，不因额外检查步骤引入归因混淆。这是论文的主实验；
> 五类消融等其余设计降为辅助（§11.4）。
> 记忆模板为**事实匹配**（UNCOND/COND/COND-MINUS 共享同一失败事实，只变适用范围）；
> 模板文本在阶段 A 冻结前进预注册文档。

**维度一：环境有效性（任务内配对，within-task family）**

- **V-dead**：环境与前段相同，旧死径仍然死 → 回避它是正确行为（失败记忆应帮助）。
- **V-revived**：关键条件改变（依赖库版本升级 / 数据分布变化 / 预算扩大），旧死径
  **复活为可行路径** → 继续回避是机会损失（失败记忆应有害），测为放弃行为 + 该路径
  对应检查点失分。
- **构造要求（预注册）**：复活路径在 V-revived 中可通过检查点、在 V-dead 中确实失败
  （预跑验证）；两变体除操纵条件外逐项匹配（匹配清单进预注册文档）。
- **关键区分（评审提出，必须在设计中显式处理）**：V-revived 中重试旧路径，是
  **负迁移**（盲目禁忌）还是**正确利用带条件的历史经验**？——单看 V-revived 无法
  区分，必须与维度二交叉：只有当 agent 在"记忆已声明条件"的场景下仍系统性地
  放弃可行路径（且 COND 组比 NONE 组更差），才构成可解释的负迁移。

**维度二：失败经验的表征形式（主实验 4 水平 + 独立方法实验；模板事实匹配）**

> **模板冻结规则（v2.2，采纳第三轮评审）**：UNCOND / COND / COND-MINUS 三种记录
> **共享完全相同的失败事实**——失败路径、失败原因、观测证据、后果——全部一致；
> 唯一有意改变的是**失败结论的适用范围表述**。否则 COND 的任何优势都可能来自
> "更多解释信息"而非适用条件本身。模板文本在阶段 A 冻结前进预注册文档。

| 条件 | 保留的内容 | 唯一改变的部分 | 归属 |
|---|---|---|---|
| NONE | 无持久失败经验 | — | 主实验 |
| UNCOND | 完整失败事实（路径+原因+证据+后果） | **不说明失败结论的适用范围** | 主实验 |
| COND | 与 UNCOND 相同的失败事实 | 额外明确**适用条件**及**何种变化会使结论失效** | 主实验 |
| COND-MINUS | 与 COND **等长**、相同事实与原因 | 用**受控非诊断性内容**替代适用条件 | 主实验 |
| COND+CHECK | 与 COND 相同的记忆 | 行动前**显式适用性检查步骤** | **独立方法实验** |

> **COND+CHECK（独立方法实验，v2.3 明确边界）**：它同时增加条件信息与**显式检查
> 步骤**（=额外推理机会）。只有当额外指令、执行步数与预算控制足够严谨（与 COND
> 等步数/等 token）时才讨论其效果；否则只作描述性报告，不进主假设族、不作归因。
> 方法贡献候选身份仅在 H-A+H-B 成立且 G4 达标后提出（§18）。
>
> **UNCOND 隐含条件预试验（v2.3 新增）**：失败事实可能已隐含适用条件
> （"16GB 显存下 OOM" ⇒ 资源约束）。冻结前对每条 UNCOND 模板跑推断检查
> （模型能否从事实推出条件），结果写入预注册文档；若普遍可推断，论文主张表述为
> "显式标注的**增量**价值 vs 自行推断"（§3.2 H-C）。

**核心读数（主实验 2×4）**：{V-dead, V-revived} × {NONE, UNCOND, COND, COND-MINUS}。
**主要结果指标 = 任务成功率**（预注册加权得分），按 §3.2 H-A 方向性对比判定
（UNCOND vs NONE 分环境效应量与 CI → 方向性交互）；H-B = COND vs UNCOND
（含非劣效界值 δ，§3.2 时点纪律）；H-C = COND vs COND-MINUS。**重复死径率与
错误放弃率为 L2 解释性行为指标**（两个独立指标，不拼成统计交互），并报告
"少行动 ≠ 好结果"的分离（通过率不升而动作数下降的条件单独标注）。

### 9.3 工作示例（T1 具体化，v1.0 保留）

## 10. 评分规则（冻结，v1.0 保留）

1. **确定性优先**：能用脚本判的绝不问 LLM。
2. **语义判分**（C4/C7/C10）：judge = qwen2.5:7b，prompt 冻结、温度固定；judge 读
   检查点规格原文，不读 agent 自评；双判不一致 → 第三人/人工。
3. **E0 反循环扩展**：空记忆 + 任务描述下也不可得分的检查点标记 E0，不计入条件差异；
   E0 判定只对照任务描述与检查点规格（PROTOCOL.md §3 同款反循环）。
4. **容差预注册**：数值检查点容差冻结时定；禁止看结果后调。
5. **结果行**带 `code_commit`、条件标签、版本号、trace 引用；判分输入全部落盘可复算。

### 11.3 管线纪律（v1.0 保留）

抽取一次、结果冻结（含标签）；消融只发生在检索/上下文组装层；检索参数与论文一一致
并冻结，不许按条件调参；每条件独立 trace 全录。

### 11.4 设计减法表（v2.1 新增，采纳第二轮评审第三节）

| 设计元素 | v2.1 处理 | v2.2 修订 | 原因 |
|---|---|---|---|
| V-dead / V-revived | **核心实验**（§9.2 维度一） | 不变 | 直接检验失败经验的适用边界 |
| UNCOND vs COND | **核心干预** | **模板事实匹配**（仅适用范围不同） | 使比较接近"增加适用条件的效果"（§9.2） |
| COND-MINUS | **核心对照** | **等长 + 非诊断性替代内容** | 排除"条件化=更多信息"混淆（H-C） |
| COND+CHECK | 核心干预之一 | **降为独立方法实验**（预算受控或不作归因） | 额外检查步骤=额外推理机会的混淆 |
| NONE / token-matched / random-irrelevant | 保留关键基线 | 不变 | 排除上下文量与任意文本混淆 |
| 五类记忆完整消融 | **降为辅助实验** | 不变 | 避免一个主问题裂变成过多 RQ |
| FAIL×LINEAGE 交互 | **暂列次要假设** | 不变 | 先验证条件信息本身的作用（§11.2） |
| Oracle 三条件 | **仅在阶段 A 试点验证必要性** | 不变 | 主问题聚焦适用边界时，完整分解不必贯穿所有条件 |
| 阶段敏感性（探索 vs 延续） | **降为次级分析** | 不变 | 先把"环境适用性"变量定义清楚，避免因素过多伤统计功效 |
| RAW-TRACE / SHUFFLE | 辅助（附录） | 不变 | 服务于 v2.0 宽问题，对收窄后主问题非必需 |

分离）——三项 Holm 校正，统计功效集中。**H-A 判定不依赖单一交互显著性**（§3.2）。

## 12. 统计与分析单位（v2.0 新增；v2.1 细化任务家族）

1. **分析单位 = 任务，不是检查点**。任务内检查点相关（前期失败会连带后续失败），
   不得当独立样本。任务内检查点聚合为任务得分（通过率或预注册加权分）。
2. **任务家族（v2.1 新增，采纳第二轮评审）**：同一基础任务的 V-dead 与 V-revived
   是**配对变体，不是两个独立任务家族**。阶段 B 报告必须区分三层：独立**任务家族数**
   （上限一般化主张）→ 家族内变体（有效性操纵，配对分析）→ 变体内条件/模型/种子
   （重复测量因素）。"30–50 实例"目标按家族×变体×条件计数，家族数单独报告。
3. **推断检验**：任务级配对——Wilcoxon signed-rank（连续得分）或配对 bootstrap；
   McNemar 仅用于任务级二元结果（如"全部检查点通过"）。检查点级数字只做描述。
   双因素交互用配对的 Aligned Rank Transform 或混合效应模型（有效性×形式，
   家族为随机效应），实施细节在阶段 B 功效分析时冻结。
4. **两阶段样本量（v2.3：按独立任务家族计算与报告）**：
   - **阶段 A（证伪试跑）**：5–9 任务（含 ≥2 个完整 V-dead/V-revived 家族）×
     **最小条件集 = 主实验 2×4**（NONE/UNCOND/COND/COND-MINUS × V-dead/V-revived；
     COND+CHECK 不进阶段 A）。验证三前提：①同一失败记忆的效应随有效性**方向性
     反转**（有信号）；②事实匹配模板下表征形式可测出差异；③行为层（放弃/死径）
     与结果层可分离。本阶段只用于估计方差与规划样本量，**不产出论文级主张**，
     **不用于事后挑选非劣效界值 δ**（δ 按可接受实际损失在阶段 B 前冻结）。
   - **阶段 B（正式统计）**：主实验 2×4 + 独立方法实验（COND+CHECK）。样本量以
     **H-A 最小关心效应**做功效分析（复用 `experiments/power_analysis.py`）得出
     **所需独立任务家族数**——不预设"30–50 实例一定足够"。上限参考
     30–50 独立任务实例、≥2 任务家族域、≥2 模型（本地 qwen2.5:7b + 至少一个
     API 模型，视预算）。
   - **报告规则（v2.3）**：功效分析表与结果表必须分别列明——独立**任务家族数**
     （决定泛化主张）、每家族配对变体数（V-dead/V-revived）、模型数、种子数与
     条件数。"30–50 实例"不得解读为把这些因子相乘后的总运行次数；变体、重复
     运行与检查点均不计为独立样本。
5. **种子**：同任务多种子作为重复测量因素（按任务聚合或混合效应模型），不当作独立任务。
6. 主假设族预注册（H-A/H-B/H-C，Holm 校正）；探索性结果明确标注；全部推断基于阶段 B 数据。

## 13. 效度控制（v1.0 基础 + v2.0 补充）

1. **区分度 gate（v2.3 拆分为两问，不混用）**：
   - **G-core（核心实验可区分性，主实验必要门槛）**：阶段 A 中 UNCOND vs NONE 在
     V-dead 与 V-revived 上呈方向性差异信号（§3.2 H-A 预期方向）；无信号 → 任务
     设计失败，redesign。
   - **G-instr（仪器检查，辅助）**：ALL vs NONE 是否有差异——只验证"完整记忆系统
     优于无记忆基线"，属管线健康检查；**ALL 不在主实验条件中，不作为主实验的
     必要门槛**（v2.3 修正：不让辅助条件绑架主实验门槛）。
2. **污染控制**：检查点答案不得出现在记忆构建段（字符串 + 语义双重校验脚本）。
3. **记忆使用率**：检索命中且被显式引用的比例；极低 → "记忆存在但不用"本身是结论。
4. **专家抽查**：语义判分抽样 15–20% 人工复核。
5. **基线厚度**：NONE + RAW-TRACE + random-irrelevant 三基线。
6. **任务对匹配（v2.0）**：V-dead/V-revived 除操纵条件外逐项匹配，清单进预注册文档。
7. **跨条件同分布**：各条件注入条目的阶段/来源构成报告在案，防止条件间构成漂移。
8. **机制竞争检验（v2.1 新增）**：负迁移结果须与 experience-following 式模仿解释
   （ACL 2026，§1.4①）区分——检查 trace 中放弃行为是否伴随对失败记忆的显式引用
   （L1 信号）；COND vs COND-MINUS 分离"信息量/模仿"与"适用条件信念"两种机制。
   若放弃行为出现在未命中失败记忆的 run 中，单独报告为模仿背景率。
9. **模板事实匹配校验（v2.2 新增）**：UNCOND/COND/COND-MINUS 三种记录共享同一失败
   事实（路径/原因/证据/后果），脚本校验模板对之间的事实内容一致性（关键词 +
   语义双检）与 COND-MINUS 等长性；任何模板改动重跑受影响条件（冻结纪律）。
10. **COND+CHECK 预算控制（v2.2 新增）**：与 COND 对比时等步数/等 token；无法控制
    时只作描述性报告，不进归因。

## 17. 效果测量架构（v1.1 全文保留，编号更新）

> 回答"效果到底怎么测"。原则：**（a）效果拆成三层独立可测；（b）每种失败都能定位到
> 具体环节。** oracle 隔离逻辑从论文一（`docs/PROTOCOL.md` §6）迁移。

### 17.1 三层测量

| 层 | 回答的问题 | 指标 | 判据 |
|---|---|---|---|
| L1 使用层 | 记忆**被用了吗** | 检索命中率、进上下文率、被显式引用率 | trace 脚本，无需 judge |
| L2 行为层 | 行为**变了吗** | 重复死径率、放弃可行路径率（§9.2 新增）、探索广度、保守决策数 | 规则检测（C5 检测规则），无需 judge |
| L3 结果层 | 结果**好了吗** | 检查点通过率 | 确定性脚本 + 语义 judge 双判 |

**报告约束（冻结）**：任何条件三层同时报告。L3 有效而 L1 低 ⇒ 记忆没用上、改善另有
原因；L1 高而 L3 无效 ⇒ 用了但没用。

### 17.2 Oracle 三条件与判读规则

| 条件 | 注入方式 | 隔离对象 |
|---|---|---|
| Real Memory | 全管线（抽取→检索→组装） | 参照上界 |
| Oracle Memory | 金标准条目作 active facts 注入，走**同一**检索/组装管线 | 检索 + 组装丢失（论文一 F4/F5 类） |
| Oracle Context | 金标准条目直入上下文，绕过检索 | 推理侧不使用 |

判读：①Real 有效 → 全链路通；②Real 无效·Oracle Memory 有效 → 内容有价值，丢在
检索/组装；③Oracle Memory 无效·Oracle Context 有效 → 到了上下文但 agent 不用；
④三者皆无效 → 真阴性，如实报告。null 从"说不清"变"可定位"。

### 17.3 示例读数（构造数据，仅展示结论形状）

T2 任务 5 个的构造示例（非真实结果）：

| 条件 | 死径重复 | 检查点通过率 |
|---|---|---|
| NONE | 3/5 任务 | 44% |
| SHUFFLE | 2/5 | 56% |
| RAW-TRACE | 1/5 | 61% |
| FAIL-only | 0/5 | 67% |
| ALL | 0/5 | 78% |
| Oracle-FAIL | 0/5 | 78% |

读法：ALL−NONE=+34（记忆净贡献）；FAIL-only vs SHUFFLE=+11（类别结构有价值）；
Oracle-FAIL=ALL ⇒ FAIL 内容到位时完全贡献；Real-FAIL vs Oracle-FAIL 的 11 点差 ⇒
检索/组装丢失可定位。

### 17.4 上下文等长预算对照（BUDGET-MATCHED）

所有条件上下文 token 上限一致（按最小注入条件设定，超预算择优截断），报告每条件
实际注入 token 数。SHUFFLE 隔离"类别结构"，BUDGET-MATCHED 隔离"信息量/token 数"；
若 ALL > BUDGET-MATCHED ⇒ 超出预算的部分仍有贡献，论文中单独讨论。

### 17.5 Judge 可靠性与盲审流程

双判 + 不一致第三人；blind rejudge 复用论文一流程（`third_judge_blind.py` /
`fourth_judge_blind.py` / `rejudge_2b_blind.py`）；15–20% 人工抽查；类别打标 10–15%
人工子集校准，达标后全量打标。

### 17.6 结果报告规范（冻结）

每条件结果行必须含 L1/L2/L3 三层数字、实际注入 token 数、判分一致率；主结论只从
任务级配对检验得出；任何结论必须能通过 §17.2 判读表解释环节归属。不满足的不进论文。
