## 1. 阶段 A 目标与通过标准

阶段 A 是**证伪试跑**，不产出论文级主张，只验证三个前提（母文档 §12.4）：

| # | 前提 | 操作化 | 未达标处置 |
|---|---|---|---|
| P-A1 | 同一失败记忆的效应随环境有效性**方向性反转** | G-core：UNCOND vs NONE 在 V-dead（预期任务成功率↑）与 V-revived（预期↓）呈方向性差异信号 | 任务设计失败，redesign |
| P-A2 | 事实匹配模板下表征形式可测出差异 | COND vs UNCOND、COND vs COND-MINUS 在 V-revived 有可测差异（方向不限） | 记录为"表征形式无增量"，进 P2 证伪评估 |
| P-A3 | 行为层与结果层可分离 | L2（死径重复/显式放弃）与 L3（通过率）至少部分条件下不同向 | 检查 L2 检测规则是否过宽/过窄 |

**门槛拆分（母文档 §13.1）**：G-core（上表 P-A1）是主实验必要门槛；
G-instr（ALL vs NONE 是否有差异）只是仪器健康检查，**ALL 不在主实验条件中，
不作为主实验必要门槛**。阶段 A 可选跑 ALL/NONE 作 G-instr，不进主假设族。

## 2. 运行矩阵与样本量（四层计数）

**阶段 A 规模**：3 个任务家族 × 2 个配对变体（V-dead/V-revived）× 4 个记忆条件
× 2 次重复运行 = **48 次 agent 运行** + judge 调用。家族 B 前段另需 1 次真实探索运行。

| 层 | 阶段 A 值 | 说明 |
|---|---|---|
| 独立任务家族 | **3** | 上限一般化主张的单位（母文档 §12.2） |
| 家族内配对变体 | 2（V-dead, V-revived） | 有效性操纵，配对分析 |
| 记忆条件 | 4（NONE/UNCOND/COND/COND-MINUS） | 主实验 2×4；COND+CHECK 不进阶段 A |
| 重复运行 | 2（同参数重跑） | 重复测量因素；若输出逐字相同记 1 次有效重复并记录 |
| 种子/温度 | temperature=0.0 固定 | 本地 qwen2.5:7b；采样随机性仅来自重复运行 |

**四层报告纪律（母文档 §12.4）**：任何结果表须分列——家族数 / 变体数 / 条件数 /
重复运行数。"48 次运行"是家族×变体×条件×重复的乘积，**不得解读为 48 个独立样本**；
独立样本上界 = 3 个家族。阶段 B 所需家族数由 H-A 最小关心效应的功效分析得出
（复用 `experiments/power_analysis.py`），不预设"30–50 实例一定足够"。

**预算核对**：每次运行约 5–15 次 LLM 调用 → 阶段 A 约 600–800 次调用，
qwen2.5:7b 本地可承受（母文档 §14）。

## 3. 家族 A：缺失数据机制（域：统计分析 / T1）

### 3.1 环境工件（脚本化前段）

| 工件 | 规格 |
|---|---|
| `data/train_v1.csv` | n=2000；group∈{A,B} 各 1000；协变量 z1~N(0,1)、z2~N(0,1)；y = base_g + 0.8·z1 + 0.6·z2 + N(0,1)，base_A=10.0、base_B=7.9（**真实 Δ=+2.1**）；y 缺失机制 MAR-by-(group,z2)：P(miss\|A)=0.05+0.4·z2，P(miss\|B)=0.45+0.4·z2（clip 到 [0.02,0.9]）；种子固定 |
| `data/test_v1.csv` | 同机制 held-out 切片 n=800（V-dead 后段用） |
| `data/train_v2.csv` / `test_v2.csv` | **V-revived 操纵**：提供方重新采集，缺失机制改为仅依赖 z1（P(miss)=0.1+0.3·z1，两组相同）→ 组内删除偏差相同 → 删除法对 Δ 无偏（z1 分布两组同分布，预跑验证） |
| `tools/robust_groupdiff.py` | v1 时代写的组均值差估计工具（内部 MI，M=20，种子固定）；**含 v1 专用健全性断言**：`assert miss_rate_B > 3×miss_rate_A, "unexpected data version"` → 在 v2 数据上**崩溃**（预跑验证） |
| gold 文件 | 各切片完整数据（模拟器已知）上的真实 Δ；MI 参考估计；全部落盘冻结 |

### 3.2 前段轨迹（脚本化，6 步，供记录抽取）

1. 读取 train_v1.csv，describe（n=2000 → 有效 y 约 1200）。
2. **路径 X（死径）**：`dropna()` 后按组均值差 → Δ_X1 = **+8.2pp**（目标值）。
3. 健全性检查：与 MI 参考估计 +2.1pp 比，偏差 6.1pp > 5pp 容差 → **失败事件 E_A**。
4. 诊断：按组/按 z2 的缺失率表 → 发现缺失与分组和 z2 相关。
5. **路径 Y（修复）**：调用 `tools/robust_groupdiff.py` → +2.0pp，偏差 0.1pp ≤ 容差 → 通过。
6. 轨迹落盘，供 §3.3 记录抽取（脚本化，无需 agent 运行）。

### 3.3 FAIL 记录 F_A 三模板（逐字冻结；事实匹配）

三种条件**共享完全相同的事实串 S_A**，唯一有意改变的是失败结论的适用范围表述
（母文档 §9.2 模板冻结规则）。模板文本即注入记忆库的条目全文。

> **S_A（共享事实串）**：在 train_v1.csv（n=2000）上，按 y 列表删除缺失行后样本降至
> n≈1200，组均值差为 +8.2pp；与多重插补参考估计 +2.1pp 相比偏差 6.1pp。原因：y 的
> 缺失与分组及协变量 z2 相关（B 组缺失率约 45%，A 组约 5%）。

| 条件 | 条目全文 | 与 S_A 的关系 |
|---|---|---|
| UNCOND | S_A | 无适用范围表述 |
| COND | S_A + 「【适用条件】上述结论仅在缺失与分组相关时成立；若数据版本更新使缺失机制改变（如缺失被补齐或改为与其他变量相关），删除法结论失效。」 | 唯一增加：适用范围 + 何种变化使结论失效 |
| COND-MINUS | S_A + 「【备注】该分析于项目第 3 阶段执行，使用默认参数配置，完整中间结果见运行日志附录，未做额外敏感性检查。」 | 唯一增加：**受控非诊断性内容**，与 COND 等长（±10% 字符） |

### 3.4 V-dead / V-revived 操纵与匹配清单

| 维度 | V-dead（任务 A-dead） | V-revived（任务 A-revived） |
|---|---|---|
| 数据 | train/test **v1**（缺失机制未变） | train/test **v2**（缺失机制改为仅依赖 z1） |
| 路径 X（删除法） | 仍有偏（Δ≈+7.9pp vs 金标 +2.0pp）→ **回避正确** | 无偏（Δ≈+2.05pp vs 金标 +2.1pp）→ **回避是机会损失** |
| 路径 Y（robust 工具） | 正常 → +2.0pp 通过 | **崩溃**（v1 专用断言）→ 回避 X 且退回 Y 者失败 |
| 任务描述 | 逐字相同（除数据文件名） | 同左 |
| 检查点/容差/预算 | 逐项相同 | 同左 |

**匹配清单（进预注册）**：任务描述文本、检查点集、容差、步数预算、gold 计算脚本、
judge prompt、注入记录字数区间（±10%）——除数据文件外全部一致。

**负迁移 vs 正确利用的区分（母文档 §9.2）**：V-revived 中重试 X 不构成负迁移；
只有 agent **显式放弃可行路径 X 且引用失败记忆**（L1 引用信号）才计为
可解释的负迁移（§3.7）。

## 5. 家族 C：SQL join 扇出（域：数据库查询 / T1）

### 5.1 环境工件

| 工件 | 规格 |
|---|---|
| `db_v1.sqlite` | orders(5000 行, amount 合计 **50,000**)；customers 中 18% 的 customer_id 有重复行（大小写变体，如 'ACME'/'acme'） |
| `db_v2.sqlite` | **V-revived 操纵**：上游修复唯一性（customer_id 唯一）；新增 `canonical_name` 列（每客户唯一）；遗留 `name` 列保留大小写不一致 |
| gold | orders 表 SUM(amount)=50,000；customers 唯一客户数（v1/v2 各自冻结） |

### 5.2 前段轨迹（脚本化，4 步）

1. 路径 X：`JOIN customers ON customer_id` + `GROUP BY c.name` → 合计 **58,500**（+17% 扇出）。
2. 校验：与 orders 表 SUM=50,000 比 → **失败事件 E_C**。
3. 诊断：customer_id 重复导致订单扇出。
4. 路径 Y（修复）：`JOIN (SELECT customer_id, MIN(name) AS name FROM customers GROUP BY customer_id)` → 50,000 通过。
   （Y 按 name 聚合的写法在 v2 上会按大小写变体分裂客户 → C-C2 失败，预跑验证。）

### 5.3 FAIL 记录 F_C 模板（逐字冻结）

S_C：「在 db_v1 中 customers.customer_id 存在重复行（18% 客户有大小写变体），
直接按 customer_id join 后按 name 汇总会使订单扇出重复，合计虚增 17%
（58,500 应为 50,000）。」
UNCOND=S_C；COND=S_C+「【适用条件】上述结论仅在 customer_id 存在重复行时成立；
若上游修复唯一性（customer_id 唯一），结论失效。」；COND-MINUS=S_C+等长非诊断备注句。

### 5.4 检查点与 L2 规则

| ID | 类型 | 判据 | 容差 |
|---|---|---|---|
| C-C1 | 确定性 | 合计 = 50,000 | 精确 |
| C-C2 | 确定性 | 输出行数 = 唯一客户数（v1/v2 各自冻结） | 精确 |
| C-C3 | 语义（双判） | 结论陈述与汇总一致 | prompt 见 §7 |

## 7. 评分规则与 judge prompt（冻结）

1. **确定性优先**：C-A1/A2/A4、C-B1/B2/B4、C-C1/C2/C4 全部脚本判，不问 LLM。
2. **语义判分**（C-A3/B3/C3）：judge = qwen2.5:7b，温度 0，prompt 冻结；
   judge 只读检查点规格原文 + agent 最终输出，**不读 agent 自评、不读记忆内容**。
3. **双判不一致 → 第三人**（复用 `experiments/third_judge_blind.py` 流程）；
   15–20% 人工抽核；一致率随结果报告。
4. **E0 反循环扩展（母文档 §10.3）**：空记忆 + 仅任务描述也不可得的检查点标记 E0，
   不计入条件差异；E0 判定只对照任务描述与检查点规格（`PROTOCOL.md` §3 同款）。
5. **容差预注册**：本文档 §3.6/§4.4/§5.4 表中数值冻结；禁止看结果后调。
6. **结果行**带 `code_commit`、条件标签、版本号、trace 引用；判分输入全部落盘。

**judge prompt 骨架（冻结，C-A3 为例）**：

```text
你是论文实验的评分员。下面给出一个检查点规格和一段 agent 的最终输出。
请只根据规格判断输出是否满足要求，不要推测意图，不要奖励努力。
检查点规格：{C-A3 规格原文}
agent 输出：{最终输出}
请输出 JSON：{{"pass": true/false, "reason": "一句话引用输出中的依据"}}
```

（C-B3/C-C3 同骨架，仅替换规格占位符；判分输入落盘可复算。）

## 8. 污染校验脚本规格（`experiments/kwm_contamination_check.py`，待实现）

跑数据前必须全绿，任一失败即阻塞：

1. **金标泄漏**：各检查点金标值（+2.1pp、500,000、50,000、唯一客户数等）不得出现在
   前段轨迹文本、三模板记录、后段任务描述中（字符串 + bge-m3 语义双检，阈值 0.3）。
2. **COND-MINUS 零诊断性**：COND-MINUS 附加句与各检查点语义相似度 < 0.3；
   与 COND 附加句相似度 < 0.5（防写成同义复述）。
3. **模板事实一致**：三模板 S 部分逐字相同；COND-MINUS 与 COND 等长 ±10%。
4. **任务描述不泄题**：任务描述不得含"删除法/插补/join 扇出"等指向性词
   （白名单词表冻结：继续、完成、给出、估计、汇总等过程词）。
5. **random-irrelevant 对照素材**（阶段 A 可选）：其他家族轨迹的无关片段，
   等 token、同格式、同注入位置，同样过第 1、2 条校验。

## 9. Codebook：标签裁决与一致性

1. **失败事件标注**：轨迹中"路径 + 校验失败 + 原因"三要素齐全的步骤记为失败事件；
   由两名标注员独立标 15% 子集，**Kappa ≥ 0.7** 才进抽取；不一致按裁决规则
   （以校验器输出为准）解决并记录。
2. **FAIL 记录字段**：失败路径、失败原因、观测证据、后果（四字段必备，
   母文档 §9.2 事实匹配定义）；修复路径**不入**记录（保模板事实匹配）。
3. **主功能标签**：本阶段 A 记录全部为 FAIL 单标签；多标签记录不进阶段 A
   （多重标签处理规则见母文档 §8.3，服务于阶段 B 辅助实验）。

## 10. 预注册摘要（跑数据前冻结）

**主假设族**（Holm 校正，母文档 §3.2/§15）：

- **H-A（适用边界反转）**：主结果指标 = 任务成功率（§3.6 加权得分二值化 +
  连续得分双报）。判定：①UNCOND vs NONE 在 V-dead 与 V-revived 中**分别**报效应量
  与 CI（预期：V-dead 为正、V-revived 为负）；②再检验方向性交互。
  交互显著但两环境同向 ≠ H-A 成立。
- **H-B（条件化缓解）**：COND vs UNCOND 在 V-revived 方向性检验（预期 COND 更高）；
  且在 V-dead 中 COND 的死径重复不高于 UNCOND 超过**预注册非劣效界值 δ**
  （δ 在阶段 B 前按可接受实际损失冻结；阶段 A 只估方差，不从事后挑选）。
- **H-C（机制分离）**：COND vs COND-MINUS——控制长度与一般性附加内容后，
  显式适用条件是否比非诊断性替代内容带来额外收益。**表述纪律**：不等同于
  "彻底分离条件信念与更多信息"（适用条件本身就是决策信息）；
  若 UNCOND 隐含条件预试验（下）显示模型可自行推断，论文主张改为
  "显式标注的**增量**价值 vs 自行推断"。

**UNCOND 隐含条件预试验（母文档 §9.2）**：冻结前对每条 UNCOND 模板跑 3 次推断检查
（qwen2.5:7b："仅根据这段记录，能否说出该失败结论在什么条件下不再成立？
给出依据"）。若 ≥2/3 可正确推断 → 记录为"隐含条件高"，论文主张按上述口径表述。

**分析计划（阶段 A）**：家族内配对（V-dead vs V-revived）× 条件效应，
Wilcoxon signed-rank / 配对 bootstrap（母文档 §12.3）；检查点级数字只作描述；
阶段 A 全部结论标注"试跑性质"，功效分析与 δ 冻结留待阶段 B。

**证伪条件映射**：P-A1 未过 → G-core 失败 redesign（母文档 P1）；
P-A2 未过 → 进 P2 评估；P-A3 未过 → 查 L2 规则；P3/P4 口径见母文档 §15。

## 13. 风险与已知局限（写入论文 Limitations 的种子）

1. **V-revived 结果层对比依赖 agent 典型行为**：若 agent 总能自创正确替代路径，
   H-A 的 V-revived 有害信号只出现在 L2 行为层与 C-A4 预算层——这是设计内行为，
  不是失败；但论文不得夸大结果层效应。
2. **3 个家族的独立样本上界很小**：阶段 A 一切结论仅为试跑信号；
  泛化主张必须等阶段 B 功效分析扩家族。
3. **本地单模型**：阶段 A 只有 qwen2.5:7b；模型依赖性未测（G3 门槛内容）。
4. **步数预算可能惩罚"谨慎"**：C-A4/B4/C4 把效率写入任务描述（agent 可见），
   但仍可能惩罚细致的 agent——报告中单列"预算失败但结果正确"的 run 数。
5. **家族 B 前段单次探索**：其 FAIL 记录实例化自一次轨迹，存在轨迹特异性；
   阶段 B 应为每家族补 1 次独立探索轨迹做记录稳定性检查。
